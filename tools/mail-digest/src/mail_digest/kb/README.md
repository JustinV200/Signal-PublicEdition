# mail_digest.kb

Which `life/` files a run may edit, and the post-run guard that checks what it wrote into them.

## Public API (`from mail_digest.kb import ...`)

- `find_targets(life_dir, day)` returns `KbTargets(week, inbox, plan, courses)`, looked up at run time: `inbox.md` (or `None`), this week's plan (or `None`; week folders are named `2026-10-19-to-10-25`, Monday to Sunday) and the course READMEs of the term holding the latest week. `KbTargets.editable` is the ones that exist. Only plain files count: an Edit rule for a missing file would also cover a folder of that name. Paths that can't be an exact Edit rule (anything outside `[A-Za-z0-9._/-]`) or that go through a link or junction are skipped and logged.
- `snapshot(life_dir, editable)`: every plain file under `life/` as relative path to its bytes (the editable files and paths under them) or its SHA-256 digest (everything else), taken before claude starts and again by the guard. Links, junctions and other reparse points are skipped, and so is a file or folder that can't be read (logged).
- `guard_edits(life_dir, before, editable, rejected_dir, rules=DIGEST_RULES)` returns `GuardReport(reverted, unexpected, failed)`. Paths are compared ignoring ASCII case only (`paths.py`): NTFS and Claude Code's Edit rules fold `INBOX.MD` to `inbox.md`, but not look-alikes such as the Kelvin sign, `ſ` or `ß`. Every editable path is checked even if one fails. One that couldn't be checked (its file is there but the snapshot couldn't read it, or a save, restore or rename failed) is logged and listed in `failed`; file errors don't raise.
  - An editable file is the job's work. Every added non-blank line must end in its run's tag (`LineRules.tag`: ` (mail)` for the digest, ` (site)` for checker v2) (or be one of the routine's headings: `## Overdue`, `## Coming up`, `## For the <week> plan`), be at most 300 chars, and use only allowed characters: letters, marks and digits of any script (so accented names work), the plain space, the no-break spaces U+00A0 and U+202F, and `. , : ; ! ? - ' " ( ) / % # & @ + * | [ ] _ =` plus en and em dashes, curly quotes, the no-break hyphen and `… • · → € £ ° ® ™`. That's an allowlist, so everything else fails: backslash, backtick, `<`, `>`, `{`, `}`, `~`, `^`, `$` (it opens math, where `%` starts a comment that hides the rest of the line), emoji and other symbols, tab and other control, format, unassigned or space characters (lines are split on `\n` only, so a lone `\r` or U+2028 stays in its line and fails this). It also must not have a letter or mark that renders as nothing (variation selectors, the combining grapheme joiner, Hangul fillers and the like), an overlay mark (combining class 1, such as U+0336, a fake strikethrough), an enclosing mark (category Me, such as U+20E0, a "no" sign), more than 3 marks in a row, or any of these sequences: a URL (`//`, with a scheme or without, or `www.`), Markdown link or image (`](`), link definition (`]:` anywhere, so also one in a list item or quote, and the Markdown comment `[//]: # (...)`), character reference (`&#` or a named one such as `&zwnj;`) or 6+ digit number. An added table row (`tables.py`: any line below a delimiter row, up to a blank line) must not have more cells than the delimiter row, since GFM and VS Code drop the extra cells and their text. A delimiter row needs no `|` (in GFM `:---` makes a 1-cell table under any header line, and in VS Code `:---` or `---` does under a header with a `|`), its spacing may include `\v` and `\f` as GFM allows, and one inside an open table (no blank line between two tables) can only narrow the width, as renderers keep the first table's. The tag counts as a cell, so it goes in the last one (`| Wed | Exam | 25% (mail)`). Bare domains, spaced-out digits, non-decimal digits (circled or superscript ones don't count toward the 6) and email addresses (GFM links them, `mailto:` and `xmpp:` forms too) still pass. At most 60 lines (blank ones included) may be added and 5 non-blank lines removed; a changed line counts as both. A file that had HTML before the edit (`HTML_START`: `<` and then `!`, `?`, `/` or a letter, so comments, tags, autolinks and placeholders such as `<date>`) takes no edits, since an added line could land inside a hidden comment or block. Nor does one with a lone `\r` (not before `\n`): GFM takes it for a line ending, not spacing, and the rules split on `\n` only, so table widths would be counted from the wrong lines. A failing file is saved to `rejected_dir` and restored from the snapshot (deleted if it didn't exist). One whose name only changed case is renamed back, unless another file already has the old name (logged).
  - Anything under an editable path (`inbox.md/x.md`) is the job's work too, because Edit rules match gitignore-style. Every change there is saved to `rejected_dir` and undone, and the empty folders are removed.
  - Other files that changed are only logged, and listed in `unexpected` for the runner to announce. The Edit rules mean the job can't have written them, so they're someone else's concurrent edits.
- `edit_problems(before, after, rules=DIGEST_RULES)`: the line rules alone, for one file's text.
- `is_safe_text(text)`: the character and sequence part of the line rules (allowed characters, no `FORBIDDEN` sequence, no invisible letter, no long mark run), with no length or tag check. The checker runs it on assignment names before the writer sees them.
- `LineRules(tag, forbid_untick)`: which rules a run gets. `DIGEST_RULES` is `(mail)` with `forbid_untick` off. With it on (site runs), a file whose todo count (`- [ ]` and `- [x]` lines) or ticked count drops is a problem (`todo_counts.py`). The check is net-only: a tick or a move under `## Overdue` passes, and so does one untick plus one tick.
- `added_lines(before, after)`: the non-blank lines of `after` that the edit added or changed, from the same diff the line rules use. The digest email lists them.
- `find_plan(life_dir, day)`: the plan of `day`'s week, relative to `life/` (same plain-file and link checks as `find_targets`), or `None` before that week's rollover. `find_targets` uses it for this week, and the digest email for this week and next.
- `is_reviewed(life_dir, path)`: True if `git status` shows the file committed and unchanged, so a flagged file (one the guard couldn't check, or one a run stopped before its guard could) is no longer flagged. Anything else, git errors included, is False.
- `expire_notes(life_dir, relative_paths, today)`: deletes lines starting `Watch for (until YYYY-MM-DD):` whose date is before today (undated or invalid dates stay), keeping line endings; returns the removed lines. The runner calls it on the course READMEs and the plan before the snapshot.
- `fold_case(path)`: the ASCII-only case folding the snapshot and guard compare paths with.

## Files

`targets.py`, `paths.py` (ASCII case folding, shared by the snapshot and guard), `snapshot.py`, `line_rules.py`, `todo_counts.py` (the no-untick rule), `tables.py` (which lines are table rows, and their cell counts, for the line rules), `guard.py`, `review.py`, `expire.py`.

## Dependencies

`mail_digest.settings`, and `mail_digest.child_env` to run git. Standard library only.
