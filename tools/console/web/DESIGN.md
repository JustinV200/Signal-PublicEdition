# Signal console: design spec

Build contract for `tools/console/web`, a front end to the owner's main Claude Code session (Claude): typed messages go to Claude, buttons run directly in the console server, and otherwise the UI only reads status.

## 1. Concept

A radar HUD. The console opens on a scope: a dark face with range rings, a crosshair grid, a slow sweep and labelled blips for Claude, Voice, the projector, the active tasks and any request still in flight. Chat, Voice and Boards sit behind tabs beside it, a status line above, an input line below. One monospace face, one phosphor hue (cyan) for accent and glow, rules for chrome, motion that only confirms something happened. The glow stays restrained and the sweep slow and low-contrast: readability first. Usability beats the look: everything clickable is a bordered button or tab with a plain verb label, anything inert is plain text with no hover, and a button that cannot work is disabled with its reason beside it.

**Colourblind rule (so it also works for red-green colourblind users).** Colour never carries meaning alone: every state also has a label, shape, weight or position (`Running`/`Stopped` text plus filled/hollow dot, the word `failed`, `you` bold vs `claude` regular, `▸` on the selected row, the active tab filled and bold, `Showing` in bold on the board that is up, blips as disc / ring / square / diamond / half / triangle with a text label, `NO SIGNAL` in words when the sweep stops). Every such shape is `ui/Mark`'s SVG (section 5), never a font glyph. There is no red-versus-green signal anywhere: the palette is one cyan phosphor, amber for warnings and violet for failures. Only amber stays safely apart from the rest under deutan and protan vision (full-severity simulation): there violet reads as blue and cyan goes near-grey, so neither is a safe signal alone, and under protanopia the accent is close to plain text. So a failure always carries a word (`failed`, `✗ failed`, `Down`), never just its colour.

## 2. Layout

Rows: status line (fixed: a 36px title row, then the tab row), Help and the tour bar when they show (outside the view's scroller, so they show at once however far the view is scrolled, with a full-width rule under them; empty, the row takes no height), view (scrolls), the result strip (one fixed row, on every view but Chat), input line (1 to 8 text rows, fixed). Everything sits in one centred **frame** (`--frame: 132ch`, `.frame`, 24px side gutters inside it), so the app name, every view's text and the input line start at one x; rules span the full window. Chat and Help keep their lines to the reading width (`--col: 96ch`, `.col`), left-aligned inside the frame. The frame's left margin comes from the window width (`100vw`), so the view's scrollbar never shifts its text off the status line's edge, and the view keeps the bar's room whether or not it overflows (`scrollbar-gutter: stable`, on the bar's edge only: a left gutter too would push the view's text right of the status line's; a thin bar in `--border`, as on code blocks). Each view's root is `frame view`: `.view` (in `base.css`) sets only top and bottom padding, so the frame keeps its gutters.

Shared view pieces, all in `base.css`: `.view-header`, the one header line every view but Chat opens with (the HUD title, then its words and buttons; a 26px content box, so the rule under it lands at the same y on every view, then 12px down to the content); `.panel`, the one raised block (`--bg-2`, `--radius`, 12px 2ch padding, no border: it is never clickable, and outlines are for things you click); and `--label-col` (15ch), the label column of Chat, Voice, Tasks and Help, so their text starts at one x. No view opens with a standing hint: what a view is for is in Help.

- Laptop (1280-1536px): 14px type, frame about 1110px, reading width about 806px.
- 4K (≥2200 CSS px): 16px type, frame about 1270px, reading width about 920px. Nothing else widens; prose past 100ch reads worse.
- Narrow (<720px): gutter collapses to a line above the body; tabs drop their status words; the app name is hidden. The window's one grid column is `minmax(0, 1fr)`, so no long line can widen the page past the window.

Views `scope` (default and home), `chat`, `voice`, `boards`, `tasks`, `system`, `setup`: a tab click or `Ctrl+1` to `Ctrl+6` swaps the body (`Ctrl+7` and `Ctrl+8` also open System, `Ctrl+9` opens Setup); the input line stays in every view, and sending a message switches to `chat`, where the reply lands.

Scope view: `SCOPE`, then the radar (400px) beside a bordered readout of row-buttons `NEEDS YOU  say yes to the hook` (three such rows at most, then `NEEDS YOU  +16 more`) / `CHAT  2 new · last 14:05` / `CLAUDE  working 0:42 (main)` / `VOICE  running · listening · started by the console` / `BOARD  a drawing` / `YOU  away until Thu 17:00`, plus `RUNNING  Stop voice` while a button runs. Voice view: header `VOICE   ● Running · listening   started by the console   [Stop voice]`, then the feed. Boards view: header `Boards   On the projector now: the to-do list`, then a bordered list of rows like `▸ To-do list   Showing` / `  lecture   saved 2h ago` beside a preview panel of the selected row with the one `[Send to projector]` button.

## 3. Typography

IBM Plex Mono from `@fontsource/ibm-plex-mono` (400, 400 italic, 600); fallback `"Cascadia Mono", Consolas, ui-monospace, monospace`; `tabular-nums` everywhere. Form fields (`input`, `select`, `textarea`) and inline code (`code`, `kbd`, `samp`) take the app font through one `font: inherit` rule in `base.css`, never the browser's Arial or Consolas. Code blocks (`pre`, and the `code` inside one, which inherits from it) keep the browser's monospace: the bundled Plex subset has no box-drawing characters (U+2500–257F), so in Plex a table's border rows would fall back to a narrower font and come out shorter than its text rows.

| Use                                                    | Size                                                      | Weight                          | Line height                |
| ------------------------------------------------------ | --------------------------------------------------------- | ------------------------------- | -------------------------- |
| Body, input, feed                                      | 14px (16px at 4K)                                         | 400                             | `--row`: 22px (25px at 4K) |
| Status line, buttons, timestamps, gutter labels, hints | 13px (14px at 4K)                                         | 400 (`you`, primary button 600) | `--row` (inherited)        |
| Markdown h1 / h2 / h3+                                 | body +2 / body / body (16 / 14 / 14px; 18 / 16 / 16 at 4K); h2 uppercase | 600                             | 1.4                        |
| Code block                                             | 13px (14px at 4K)                                         | 400                             | 20px                       |

The body line height is the whole-pixel `--row`, so text rows land on the HUD grid (`--grid-size` is two rows). Spacing tokens `--sp-1` to `--sp-7` (2, 4, 6, 8, 12, 16, 24px) are for vertical spacing in new and touched CSS; horizontal spacing uses whole `ch`. `--radius` is 3px, `--tracking-label` 0.1em, `--tracking-heading` 0.06em (markdown h2s), `--label-col` 15ch.

## 4. Colour tokens

Dark always, whatever the OS says: a near-black scope with a teal cast. Light is included as an opt-in (`Light theme` in Commands, or System's `Light` button, sets `data-theme="light"` on `<html>` and remembers it in `localStorage`) and drops the glow. `styles/tokens.css` is the only file with literal colours (hex, `rgba`); every other style and inline style uses the tokens. Every text token (`--fg` to `--error`) reaches 4.5:1 on all three surfaces in both themes, and `--border` reaches 3:1; the ratios are computed from these values (WCAG relative luminance).

## 5. Components

**Scope** (`views/scope`, the drawing in `views/scope/radar`). One SVG, viewBox 400, drawn at exactly 400px at every width (its grid column is pinned at 400px, and it stays 400px wide in the 720px single-column layout; only a screen narrower than that shrinks it), so text never scales. Drawn entirely in `--accent` at low alpha: a face with a radial falloff (11% at the centre to 2% at the rim) and a 45% rim (`--scope-rim`, 80% in light), three range rings and a crosshair plus 30° ticks at 22% (`--scope-line`, 40% in light), and a sweep (a leading radius at 45% with an eight-step trail fading from 16% to 0) turning once every 5 s, linear: once per server keepalive. Each subsystem has a sector, its edge drawn at the rim's 45% and its name (`fg-2`, spaced capitals) in the corner beside it, outside the rim: VOICE 0–90°, BOARD 90–180°, TASKS 180–360°. Range means time or progress. Voice, the board and pending requests sit at the time since they last did something, read against the rings captioned `now`, `1m`, `5m` (centred on each ring just above the 90° line; `now` on the inner ring, linear to `1m`, then to `5m` on the rim, and on the rim when older or never). A task that isn't waiting on the owner sits at its progress (rim 0%, linear to a tenth of the radius at 100%: just outside Claude's mark rather than on it, so a finished task never covers Claude or takes its clicks). Blips: Claude at the centre (disc while its session is linked, ring when none is claimed or it closed; label `CLAUDE · <turn words>|no session|session closed|not connected`, the status line's words, below it, `state unknown`'s cause included; a ring with a slow pulse, `anim-pulse-slow`, while only its agents run); Voice at 45° (disc running, hollow ring stopped; `VOICE · listening|thinking|speaking|stopped`; range from its newest feed event); the board at 135° (square while the whiteboard is on, hollow ring while off; `BOARD · the to-do list|a drawing|nothing|off`; range from its newest button row); up to four pending requests beside their subsystem's blip, 25° then 38° either side (diamonds; the action text; the same pending rows as the buttons, so only requests this page sent, until done, failed or two minutes old; range from when it was sent); and the tasks. The ordinary ones are half discs spread evenly across TASKS less 30° either side of 270° (the horizontal through Claude), most finished first from the top down; label `<name> <pct>%`, never the status number. The tasks that need the owner are not drawn one by one, since the readout says what each needs: together they are one triangle in `--warn` whose bold label says how many, `19 NEED YOU` (`1 NEEDS YOU` for one; no triangle when none waits), and none of them takes a place in the spread. Its spot is fixed and kept clear by the geometry, so the count can never be covered or cut: on that horizontal at 270°, 0.9 of the radius out (inside the rim and its tick), the label running in along the line. The 30° band keeps every ordinary mark off that line out there (the nearest a half disc comes to it is a nearly finished task beside the centre, 23 units past the end of a three-digit count); Voice, the board, their requests and the ring captions are all on the right half, the banner is far above, and Claude's label is one line lower. A click on a blip or its label opens its view (Claude: Chat, Voice: Voice, board: Boards, a request: its view, a task or the needs-you count: Tasks); the SVG stays hidden from screen readers and out of the tab order, since every view a blip opens is also a readout row. Only a mark glows (`--glow` drop shadow) and pulses (`anim-pulse` while its thing is in flight: Claude busy, a pending request); labels never glow or blink. All text is `--font-small` with a halo in `--bg` (`paint-order: stroke; stroke: var(--bg); stroke-width: 3px`) on a plate of `--bg` at 85% (the halo hugs each glyph, so without the plate the crosshair still ran through the gap in `CLAUDE · idle`). Labels are horizontal beside their mark, towards the centre first, else away from it, each cut with an ellipsis (a task keeps its percent; 28 characters at most) to stop short of the rim and of anything already placed on its line. A crowded face hides labels, never marks: labels are placed in priority order (first the two pinned ones, Claude's below the centre and the needs-you count's on the left horizontal, which are not fitted around anything and always show whole in their own spots; then Voice, the board, pending requests, then the tasks most finished first), and one that can't keep 4 characters of its name on either side hides, with its full words as the mark's hover title. While the stream is stale (no byte for 20 s, the status line's own test) or has dropped, the sweep stops at 0° and `NO SIGNAL 25s` (the last byte's age, in `--warn`, bold) shows above the centre: the words carry it, not the stillness. Before the first byte of a fresh load nothing shows (the sweep waits), so the banner never flashes on each load. The sweep and pulses also stop when the document is hidden (`usePageVisible`) and under reduced motion.

**Scope readout** (`views/scope/readout.ts`). Beside the radar, the same facts as text, starting with what needs the owner, so the picture is never the only copy. A bordered list (`--rule` border and dividers, hover `--bg-2`, focus ring inside the row); each row is a button, its key a HUD label in an 11ch column and its value in `fg` on the same baseline, and a click, Enter or Space opens its view. Rows in order: `NEEDS YOU` (one for each of the first three tasks waiting on the owner, its `you` text, then one `+16 more` row for the rest, so the rows add up to the radar's `19 NEED YOU`; `nothing` when none) opens Tasks; `CHAT` (`2 new · last 14:05`: Chat's new count, the words the tab and window title use, and the clock of the last row; `nothing new` at 0) opens Chat; `CLAUDE` (the turn words with the cause, as the status line and the Claude blip say them, then the session label in brackets) opens Chat; `VOICE` (`running · listening · started by the console` or `stopped`) opens Voice; `BOARD` (the words of `board.view`, or `off` while the whiteboard is off, the same words as the board blip: `blips.ts`'s `boardWords`) opens Boards; `YOU` (System's away words, lower-cased: `here`, `away until Thu 17:00`, `asleep (sleep mode)`; `unknown` when unreadable) opens System; and one `RUNNING` row per button request still in flight (the pending rows the buttons and blips share), opening Voice for a voice button and Boards for the rest, shown only while it runs. While the server isn't answering, every value ends with ` (last known)`. A value stays on one line at 1280px, cut with an ellipsis when too long (the full text is the row's tooltip); below 720px, where there is no hover, it wraps instead.

**Stream.** A message is a row: gutter `HH:MM  role` (13px, `fg-2`) in the label column (`--label-col`, 15ch), then the body. `you`: label 600 in `fg`. `claude`: label `fg-2`, body markdown, unprompted replies included. `action`: label `action`, body `fg-2`. `note` (a console notice from the `note` event, e.g. `Messages now go to the session labelled "main" (linked 3 hours ago).`): label `note` 600 in `--warn`, body 600 in `fg`, so the label text, weight and colour each mark it. A `fg-3` centred divider marks a day change. Rhythm: messages sit 16px apart (8px above and below each row), further than the 12px between paragraphs of one reply; back-to-back `action` rows sit 4px apart; a body stops at a 76ch measure. Delivery: _sending_ chat body at 60% opacity (an `action` row never fades: its `sending…` says it); _sent_ full; _failed_ adds `failed: <error>` in `--error` under the body with a Retry button (re-sends as a new message). An `action` row ends with where its run has got to, in `fg-3` after `·`: `sending…`, `working…` (the server is running it) or `done: <what happened>` (`sent` only on replayed rows from before buttons ran in the server); a failed run gets the `failed: <error>` line. `state/actions/actionProgress.ts` derives it from the row's `delivery` (`running`, `done` with `result`, `failed` with `error`), and the same derivation keeps the button that sent it in its pending state and plots the scope's pending blips (only rows with a local origin, so a replayed row never pends; capped at two minutes so a lost result cannot wedge it).

**Working indicator.** `orchestrator.turn` comes from Claude's turn hooks (a sent request reads `sent` until its turn starts). While its `state` is `working`: a last row `claude  working 0:42` ticking `m:ss` since the turn's `startedAt`, and the segment reads `Claude · working 0:42` (` · 5 agents` added while subagents run). The other states read `Claude · waiting on 5 agents`, `Claude · quiet for 12 min (interrupted?)` (stale, also in `--warn`), `Claude · state unknown until its next turn` and `Claude · idle`; while the console's Turn hook check fails, `state unknown` reads `Claude · state unknown · turn hook missing` instead (in `--warn`), on the status line and the scope alike; a closed session never shows working, whatever its last turn said; a `?` after the agent count means the two sources disagree and the lower is shown. `status/turnWords.ts` holds the wording (`turnCauseWords` adds the cause; the status line and the scope both use it). The clock is the signal; no spinner.

**The `state unknown` cause.** `Claude · state unknown` takes its cause from the console's health checks (turn hook missing versus no turn yet), through `status/turnWords.ts`'s `turnCauseWords`, so the status line and the scope's Claude blip and readout read the same:

| Cause (from `GET /api/health`) | Status line reads (the scope: the same after `CLAUDE · `) | Tooltip adds | Warn |
|---|---|---|---|
| Turn hook check not ok (`turn-hook` is `fail`: missing or partly missing) | `Claude · state unknown · turn hook missing` | the check's sentence (`Not registered for Stop, …`), `System's Console group has the fix and its command.`, the session line | yes |
| Turn hook installed, no turn since the server started (any other case, health not read yet included) | `Claude · state unknown until its next turn` (unchanged) | the session line | no |

The live region speaks the same words (they hold no clock). The status line's pointer (`✗ Turn hook: missing · see System`) leads to the fix in the first case.

**Result strip** (`app/ResultStrip.tsx`). One line above the input line on every view but Chat (Chat's action rows carry their own outcome and Retry), in `--font-small` `fg-2`, for the newest action this page sent from any button or command (`state/actions/lastActionRow.ts`): `Send to projector: "lecture" · done: Sent "lecture" to the projector.` for 30 s after the page heard it (or until the next action), or `Send to projector: to-do list · failed: The whiteboard is still busy with the last button; wait for that to finish.` with `[Retry]` and `[Dismiss]`, until dismissed or the next action. `failed` is a 600 word in `--error`; the word carries it. Empty while an action runs (its button reads `Working…`) and for rows the server replays, so a reload never shows an old result. Retry runs the same action and args through the confirm gate, so a load over a drawing put up since then still asks; Retry and Dismiss send focus back to the input line. Its row is always there, empty when idle, at a fixed height (a button's height plus 4px above and below; two text rows below 720px, where the words wrap onto both) with its words on one line above 720px (a long error ends in an ellipsis, with the whole line as the tooltip and in full in Chat), so a result arriving never moves the view or the input line. Only the words are the `role="status"` live region, with Retry and Dismiss after it, so a screen reader reads the result, never the buttons, on each change.

**Input line.** Textarea (placeholder `Message Claude…`) behind a `›` glyph (`fg-3`, `accent` when focused), caret in accent, grows 1 to 8 rows then scrolls, followed by a `Commands` button (hint `Ctrl+K`) and a primary `Send` button (hint `Enter`; while the draft is empty it is off but solid-bordered, waiting, with `type a message first` as its tooltip; while no session is linked it is dashed with `no Claude session yet` or `Claude session closed` as its tooltip, and Enter sends nothing either. The reason is never a caption, so typing never moves Commands or Send). Enter sends, Shift+Enter newline. Up on an empty or unedited draft recalls sent messages (last 50, `localStorage`, so they survive closing the window), Down goes forward, typing leaves recall. _Confirm mode_ replaces the textarea with the question in 600, then a `Yes` button (hint `y`) and a `No` button (hint `n`): `Flash calibration markers on the projector?` or `Replace what is on the projector with "lecture"? Anything unsaved there is lost.` A click, or `y` / `n` / Esc wherever focus is (the keys are global while it asks), answers it. One rule decides what asks, for the buttons and the palette alike (`state/actions/confirmRule.ts`, through `useConfirmGate`): only Full calibrate, and loading a save or showing a save's live version while a drawing is up (`board.view` is `items` and the whiteboard has not reported zero items; `board.itemCount` is the whiteboard's `item_count`, and null, from an older build that sends none, counts as a drawing), since both clear the board first. A save whose refresher is `todo` is the exception: its live version runs `todo show`, a view switch that keeps the drawing, so it never asks. The to-do list and idle board are view switches and never ask; voice and realign run at once. _Command mode_ (`Ctrl+K` or Commands): glyph becomes `:`, the clickable matches rise above the line, `▸` in the glyph's column and each label on the typed text's column. The list is 8 rows high and scrolls, keeping the selected row in view, and while more than 8 match a last line reads `+ 11 more: keep typing`. Commands and Send stay where they are: Commands (`aria-expanded`) closes the list again, and Send is off with the quiet reason `Commands is open: Enter runs the picked command`. The textarea is the list's `combobox`, its `aria-activedescendant` the selected row. Every label is a button's own words, and only the commands that apply now are listed, fixed ones first and saved boards last: `Start voice` while voice is off or `Stop voice` while it runs; `Send to projector: to-do list` and `Send to projector: idle board` (left out only when the whiteboard is on but reports no view; the Boards rows are `To-do list` and `Idle board` under its `Send to projector` button, and the chat row reads the same); `Realign whiteboard` and `Full calibrate` (both left out under the night view); `Go to Scope|Chat|Voice|Boards|Tasks|System` and `Open setup`, less the open view; `Light theme` while dark or `Dark theme` while light; `I'm away` while Here or `I'm back` while Away (neither while Asleep, which sleep mode decides, or while away mode can't be read), the same `POST /api/away` as System's YOU, for its default 3 days, a failure landing in Chat as a note; `Help`; `Refresh` (the status line's Refresh, which shows there only when stale or offline); then `Send to projector: "lecture"` per saved board, quoted like the chat row. Every typed word must appear in the label, in any order, case and `'`, `"` and `-` ignored (so `send`, `projector`, `to-do`, `todo` and `im away` all find theirs); a new query selects its first match. Up/Down, Enter runs (through the same confirm rule), Esc closes.

**Voice.** Tab: dot plus phase text, a filled disc when running, a ring when stopped (`ui/Mark`); text `listening` / `thinking` / `speaking` / `stopped`. View header: `Running · <phase>` or `Stopped`, `started by the console|started outside the console` (`status/startedByWords.ts`; the server's `startedBy` is `console` or `external`), then one button that runs right away (no confirm) and whose label follows Voice's state (`views/voice/voiceButton.ts`): `Start voice` while stopped, `Stop voice` while running, `starting` included (the server lets a stop through while a start is still loading Voice, so a slow or hung start can be stopped). It reads `Working…` only while the action named on it is pending, so a start that is still loading shows an enabled `Stop voice`. Feed rows `HH:MM:SS  kind  text`, the time (9ch) and the kind together filling the label column: `heard` quoted, `said` plain, `note` in `fg-3`. Newest at the bottom, auto-follow. Empty: the shared empty state, `NOTHING HEARD YET` and `When Voice hears or says something, it shows here.`

**Empty states** (`empty/EmptyState.tsx`). ## 6. Motion

`--ease-out: cubic-bezier(0.2, 0, 0, 1)` for things that appear, `linear` for colour. Nothing bounces; nothing animates on initial load or SSE replay.

| Trigger                           | Animation                                                                                                                                                                                |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Message or feed row appended live | opacity 0→1, translateY 4px→0, 160ms ease-out                                                                                                                                            |
| Working row appears / leaves      | opacity 120ms ease-out / 120ms linear                                                                                                                                                    |
| View switch                       | incoming opacity 0→1 + translateY 3px→0, 140ms ease-out; outgoing removed instantly                                                                                                      |
| Tab status text changes           | new text opacity 0→1, 120ms (span keyed by value)                                                                                                                                        |
| Help panel opens                  | opacity 0→1, 120ms ease-out; close instant                                                                                                                                               |
| Scope sweep                       | rotate 360° every 5s (one server keepalive), linear, infinite; the animation class is dropped while the page is hidden or the stream is stale (`NO SIGNAL`), so it restarts at 0° |
| Blip in flight                    | `anim-pulse` (opacity 1↔0.35, 1200ms)                                                                                                                                                    |
| Phase dot                         | listening: static. starting and thinking: opacity 1↔0.35, 1200ms ease-in-out, infinite alternate. speaking: three 2px bars scaleY 0.3↔1, 900ms ease-in-out, infinite alternate, staggered 0/150/300ms |
| Palette opens                     | opacity 0→1, translateY 4px→0, 120ms ease-out; close instant                                                                                                                             |
| Row, tab and button hover         | background-color and border-color 80ms linear                                                                                                                                            |
| Sending → sent (chat rows)        | opacity 0.6→1, 120ms linear                                                                                                                                                              |
| `↓ N new` pill                    | opacity 120ms; click scrolls `smooth` (instant under reduced motion); live auto-follow is instant                                                                                        |

`prefers-reduced-motion: reduce`: no translates, no infinite animation (the sweep stands still, dots and blips stop pulsing; the words carry the state), opacity fades at 80ms.

## 7. Keyboard and focus

| Keys                                     | Action                                                                                      |
| ---------------------------------------- | ------------------------------------------------------------------------------------------- |
| printable key but Space, outside a field | focus the input and insert it (from a button, tab, row or checkbox too; not a text field)   |
| Enter / Shift+Enter                      | send / newline                                                                              |
| Up / Down on empty draft                 | history recall                                                                              |
| Ctrl+K                                   | command mode                                                                                |
| Ctrl+1 to 6                              | scope / chat / voice / boards / tasks / system (Ctrl+7, Ctrl+8: system too); Ctrl+1 is home |
| Ctrl+9                                   | setup, whether or not its tab shows                                                         |
| Left / Right, Home / End                 | on a tab: move focus along the tab row; Enter or Space opens it                             |
| Esc                                      | close the palette or confirm, else help, else only focus the input; never changes view      |
| y / n while the confirm asks             | answer Yes / No, wherever focus is; holding the key answers once and types nothing          |
| PageUp / PageDown / Ctrl+End             | scroll the view from the input; jump to bottom                                              |
| Up / Down in boards                      | move `▸` only; the preview's buttons send                                                   |

`:focus-visible` is a 1px solid `--accent` outline, offset 2px, no glow. The input shows focus by the `›` turning accent and its top rule brightening to `--fg-3`. Focus returns to the input after any action, confirm, model pick or view switch. A view switch opens the view at its top, except Chat and Voice, which open at their end; a row landing at the end taller than the view shows from its top, with the `↓ N new` pill. Buttons, tabs and board rows are real `<button>`s with the bordered looks in section 5; nothing clickable is styled as plain text, and nothing inert gets a hover state.

## 8. Rendering Claude's text

`react-markdown` + `remark-gfm`, producing React elements (never `innerHTML`). Raw HTML shows as literal text. `urlTransform` keeps `http:`/`https:` only; other hrefs render as plain text. Links: `<a target="_blank" rel="noopener noreferrer" title={href}>`, accent, underline at 50% alpha, full on hover. Images never fetch: rendered as a link `[image] alt`. Bodies get `overflow-wrap: anywhere`.
