# state/actions

The life of a request the page sends (a typed message or a button's action), inside the `state` package.

- `sending.ts`: optimistic send for text and actions; `[retry]` re-sends the origin as a new message.
- `actionLabels.ts`: `actionLabel(action, args)`, the words for an action: the row's placeholder until the server's echo, and the palette's command labels. Save names go through `quoteName`, which matches the server's `_quoted` (`actions/plans.py`) exactly: JSON quotes, every letter as typed (non-ASCII too), and quotes, newlines, controls, bidi and other invisible characters (format characters by category, plus an explicit list of default-ignorable ones such as Hangul fillers and variation selectors, shared with the server) escaped as `\uXXXX`, so a name can't pass for the words around it. The confirm question quotes with it too.
- `confirmRule.ts`: `confirmPrompt(action, args, board)`, the one rule for which actions ask first and what they ask: a full calibrate, and `board.load` or `board.update` while a drawing is up (`Replace what is on the projector with "<name>"? Anything unsaved there is lost.`), since both clear the board first. An update whose save's refresher is `todo` doesn't ask: it runs `todo show`, a view switch that keeps the drawing. Everything else, voice included, runs at once.
- `useConfirmGate.ts`: `request(action, args)` puts the question on the input line when the rule asks, else runs the action; `answer(yes)` runs the waiting action on yes and closes the line either way. The Boards and Voice buttons, the palette, the Yes / No buttons and the y / n keys all use it.
- `actionProgress.ts`: where a sent action has got to, read off its `delivery` (`sending`, `working` while the server runs it, `done`, `failed`; `sent` only for replayed rows from before buttons ran in the server); and which rows and action names are still pending (local origin only, capped at `PENDING_MAX_MS`), shared by the buttons and the scope.
- `lastActionRow.ts`: `lastActionRow(messages, now)`, the row the result strip reports: the newest action this page sent (a local origin, so never a replayed row) when it failed, or finished less than `DONE_SHOW_MS` (30 s) ago, counted from `settledAt`; null while it still runs. `doneClearsAt(row)` is when a done row leaves the strip (null for any other row), so the strip sets one timeout instead of ticking.
- `usePendingActions.ts`: binds the pending set to the store for the buttons, ticking so the cap can lift a wedged one.

Entry point: `index.ts` (re-exported by `state/index.ts`). Depends on `api`, `time` and the `state` reducer, boards rules and store.
