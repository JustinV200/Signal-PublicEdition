# state

The console's in-memory state and the lifecycle that feeds it.

- `types.ts`: `AppState`, `StoreAction` and their parts (`View`, `Connection`, `LocalMessage`, `ConsoleHealth`, and the rest).
- `reducer.ts`: `reduce`, `initialState`, `startState`, `VIEWS`. Auth (with `signOutReason`, the server's words, which a keyless focus retry's plain `not signed in` doesn't overwrite, and `openCommand`, cached from each state and 401 so it still shows while the server is down), connection (offline keeps `since`, when the outage began, across retries), server snapshot, the task list (`tasks` events), messages with local delivery status (console `note` events land here as `note` rows; `settledAt`, when the page first heard a row's done or failed, which a replay never moves), how many of the reply and note rows the owner has seen (`chatSeenCount`: Chat's `chatSeen` action, sent while it is open at the bottom, sets it to all of them; a row the server replays from before the page's first server event, `openedAt`, counts as seen, so history is never new) and `chatNewCount(state)`, the rest (the Chat tab's and the window title's `N new`), voice feed, view (`scope` is home; `startState` opens on the view the URL asked for), input mode (a confirm carries the action and its args), the boards selection (`boardKey`, the selected row's key, so a new save arriving above it does not move it), help panel, `setupTool` (where the setup wizard opens), `setupCheck` (the Down row a System `Fix` opened Setup with: its tool page leads with it; leaving Setup drops it, the wizard's own `openSetup` with no tool keeps it), `setupPage` and `setupDrafts` (the wizard's open page, by its key such as `tool:mail`, and what was typed in its fields: kept across view switches, so leaving Setup and coming back finds both; an `openSetup` jump or a `#t=` link sets the page to its tool), `setupPicks` (the picked tool ids from the last `setup list`, for the tour), `tourStop` (the console tour's stop; starting or moving it opens that view and closes the help panel, so the two show one at a time, and while it runs a `view` to one of its stops moves it there), `health` (the console's own checks: rows, error, loading; `app`'s `useConsoleHealth` fills it) and `healthTick` (bumped by System's `Check again`), `syncedAt` (when the server last sent anything) and `refreshTick` (bumped by the Refresh button).
- `dedupe.ts`: id-keyed insert that keeps time order and the first event per id (the server replays events on every connect).
- `boards.ts`: board rows (to-do list, idle board, then saves) with the action that puts a row on the projector, each row's key (`boardRowKey`, `action:name`) and `boardIndexOf` (the to-do row when a key is gone), whether a drawing is up (`isDrawingUp`: view `items` and an item count that is not 0), whether the to-do list can be requested (off only when the whiteboard is on but reports no view), which row is showing (only the to-do and idle rows can be: `board.view` is `todo`, `idle` or `items`, never a save name), the words for the view (`boardViewWords`) and the Boards tab's short word (`boardTabWords`); each row's `updateArgs` (for `board.update`: only a save with a refresher), the preview's buttons per row (`boardButtons`: one primary, `Show live version` then `Show saved copy` for a live-data save, else `Send to projector`) and the night-view reason that disables Realign and Full calibrate.
- `claude.ts`: whether a Claude session is linked (`claudeLink`: `none` when nothing claimed the console, `closed` when the claimed session's inbox is gone, `linked`), the Send button's `sendBlockedReason` for the first two, `CLAIM_SENTENCE`, what the owner pastes into Claude Code to link it, and `PASTE_INTO_CLAUDE_NOTE`, the note after copying something to paste there (Chat's claim help, the wizard's hand-off). A closed session is never shown busy, whatever its last turn said.
- `actions/`: optimistic sending, action row labels, which actions ask first and the gate every button and command runs through, where a sent action has got to and the set still pending (see its README).
- `session.ts`: `takeHashLink` pulls `#k=<key>` (and `&v=<view>&t=<tool>` from `console open --view setup`) out of the URL before render; `startSession` redeems it for a token and fetches the first snapshot; a 401 anywhere is `out`, with the server's reason and command line.
- `useConnection.ts`: `checking -> in | out`, the event stream while `in` (resynced on a `refreshTick` change, when the page becomes visible again and on `online`), retry on hashchange/focus while `out`.
- `store.tsx`: `StoreProvider` and `useStore()`.
- `prefs/`: the preferences kept in localStorage: the dark/light theme (`currentTheme` reads the one on the page now) and the console tour's stops in order (`tourStops(picks)`) and last stop (`resumeTourStop`, `saveTourStop`) (see its README).

Public API: `index.ts`. Depends on `api` and `time`.
