# app

The top of the tree. `App` mounts the store and gates on the session: `SignIn` on 401, nothing while checking, otherwise `Shell` (status line, `help`'s panel and tour bar between it and the view, outside the scroller, so they show at once however far the view is scrolled, the server-down notice, one scrolling view, the result strip on every view but Chat, input line, global keys). `Shell` also asks `views/setup`'s `useSetupTab` whether the Setup tab shows and passes that to the status line, and mounts `useConsoleHealth`. A view switch opens the new view at its top (the views share one scroller), except Chat and Voice, which follow their own end (`scroll`). It keeps `document.title` on the counts (`status`'s `windowTitle`: `(2 new, 1 needs you) Signal console`), back to `Signal console` when it unmounts (signed out).

- `SignIn.tsx`: the signed-out page in the app's frame: the name, the server's reason (`That login key is wrong, used or expired.` reads differently from `Not signed in.`) and the `console open` command with Copy (`ui`'s `OpenCommand`).
- `OfflineNotice.tsx`: once the server has not answered for 10 s (`OFFLINE_NOTICE_MS`), a block at the top of the view says so in words, that the page reconnects by itself, and gives the cached command with Copy.
- `ResultStrip.tsx`: one fixed row above the input line for the newest action the page sent (`state`'s `lastActionRow`): `<action> · done: <result>` for 30 s, or `<action> · failed: <error>` with `Retry` (the same action, through the confirm gate) and `Dismiss`, until dismissed or the next action. Always there, empty when idle, one line high (two below 720px, where the words wrap), so a result never moves the view or the input line. Only its words are the `role="status"` live region, so Retry and Dismiss are never read out with each change; a done result clears on one timeout, not a ticker. `Shell` keeps the dismissed row's id, so a dismissal outlasts a visit to Chat.
- `useConsoleHealth.ts`: reads the console's own checks (`GET /api/health`) into the store's `health`: once at sign-in (the status line's pointer and the `state unknown` cause need them), each time System opens (leaving doesn't count), on Refresh and on System's `Check again` (`healthTick`); never on a timer. A failed read keeps the last rows with its reason; a 401 signs the page out.
- `app.module.css`: the scrolling view, the signed-out page, the notice and the result strip.

Public API: `index.ts`. Depends on `api`, `state`, `status`, `help`, `views/*` (scope is the landing view), `input`, `keys`, `ui` (`OpenCommand`, the strip's buttons) and `time` (the notice's ticker).
