# views/chat

The session log. `ChatView` lays out `DateDivider`, `MessageRow` (you / claude / action / note; an action row ends with where its run has got to: sending, working, done with what happened (`sent` only on replayed rows from before buttons ran in the server), and a failed one adds the error and a Retry button), `WorkingRow` (the `working m:ss` clock while Claude is busy) and `EmptyChat`, and follows the bottom through the `scroll` package (a tall reply from Claude that arrived after the view opened shows from its top, with the pill; replayed history and your own sends always land at the end). While it is scrolled to the bottom and the page is visible it sends `chatSeen`, which clears the Chat tab's and the window title's `N new`; rows that land while the page is hidden (minimised, or another browser tab) stay new until it shows again at the bottom. The view sits on the shared frame (one left edge with the status line) with its lines kept to the 96ch reading column and each body to a 76ch measure. Messages sit 16px apart, further than the 12px between a reply's paragraphs (`markdown`), and back-to-back action rows 4px apart. Only a chat row fades while sending; an action row's `sending…` says it. `EmptyChat` is the shared `empty` state (`NO MESSAGES YET`) with the linked session and how to send, or the claim help, under it.

While no Claude session is linked (`state`'s `claudeLink`: never claimed, or the claimed one closed), `ClaimHelp` names the cause (`No Claude session yet.` or `Claude session closed.`, in 600) and gives the sentence to paste into Claude Code with `ui`'s `CopyButton`. It leads an empty Chat (in place of the linked session's line and how to send) and follows the last message otherwise. Send is off meanwhile (`input`).

Public API: `index.ts`. Depends on `state`, `markdown`, `time`, `scroll`, `empty` and `ui`.
