# views/boards

The boards buffer. `BoardsView` shows what is on the projector in words (`the to-do list`, `the idle board`, `a drawing` or `nothing`: the whiteboard reports `todo`, `idle` or `items`, never which save is loaded) in the shared view header, a list of `BoardRow`s (to-do list, idle board, then each save with `saved <relative>`; a bold "Showing" tag on the to-do or idle row while its view is up) and a `BoardPreview` of the selected row, on the shared `.panel`: name, description, save time and its buttons (state's `boardButtons`, one primary each): "Send to projector", captioned in `--fg-2` that it replaces what is showing, or for a save drawn from live data (a `refresher`) "Show live version" (`board.update`, captioned that it redraws from the live tasks, the live to-do list or live data, after its refresher, and puts it on the projector) beside "Show saved copy" (`board.load`). Under the night view the caption says instead that boards sent stay hidden until it ends (the whiteboard keeps them under the night sky). The preview is sticky, so it stays in view while a long list scrolls (two-column layout only). Row hover fills `--bg-3`, like the selected row, which also has the `▸`. A row click, focus or Up/Down (on the list or from the input line) only selects; the `▸` cursor (`ui`'s triangle mark) lives in the store as the row's key (`action:name`), so a new save arriving above it leaves it on the same board (the idle row when that board is gone), and focus follows it. While a drawing is up (`board.view` is `items`), sending a save, or showing its live version unless its refresher is `todo` (a `todo show` view switch keeps the drawing), asks first on the input line (`Replace what is on the projector with "<name>"? Anything unsaved there is lost.`); the to-do list and idle board never ask. A button is pending ("Working…") while the console runs its action, and disabled with a reason for the to-do list and idle board only when the whiteboard is on but reports no view (an older build). When the whiteboard is off it lists no saves and a note says that sending the to-do list or idle board turns it on; when it is on with no saves, the shared `empty` state sits under the two fixed rows (`NO SAVED BOARDS`, `Ask Claude to save a board and it's listed here.`). The preview is text only until the whiteboard offers thumbnails.

The header also has `Realign whiteboard` (`board.realign`, no confirm) and `Full calibrate` (`board.calibrate`, through the Yes / No confirm line), both disabled under the night view, the reason said once in a note under the header (so the header stays one row) and as a tooltip only on both buttons (`quietReason`). Every button runs through the state's confirm gate (`useConfirmGate`), the same rule the palette uses.

Public API: `index.ts`. Depends on `state`, `time`, `ui`, `empty`, `input` (focus helper).
