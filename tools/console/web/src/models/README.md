# models

The model strip (`ModelStrip`), System's MODELS group, in body text. Its two rows share one grid (`display: contents` rows), so the pickers line up; each picker follows its visible label (`model`, `effort`), and each row's note sits on a line of its own under the pickers. The `Claude` row shows `now: opus-5-5 · medium` (the linked session's model from the session hook and its last Stop's effort; `model unknown` / `effort unknown` while unknown) and the next-session pickers, which write `.claude/settings.local.json` and say `applies to every new Claude session, not this one`. A hint says this Claude session switches now from the model name under the VS Code prompt box. With no session linked it reads `now: no Claude session`. The voice row's pickers write voice's pick and say `applies on your next request`.

Each picker (`PickSelect`) is a native select over the server's fixed list (`models.choices` in `/api/state`); a pick sends its index through `pickModel` (POST `/api/models`), never text, and returns focus to the input line (`input`'s `focusInput`), so a letter typed next can't change the pick by type-ahead. Null options read `use my user settings`. A current value that isn't in the list shows as a disabled placeholder (`audiohub.toml default` for both voice pickers while voice has no pick of its own, so audiohub.toml decides both; `other: X`), and an unreadable settings file shows `can't read settings`, never `use my user settings`. The pickers are disabled with a reason while saving or when the settings file can't be read; a refused write shows its error under the strip. `modelWords.ts` holds the wording.

Public API: `index.ts` (`ModelStrip`). Depends on `api`, `state` and `input`.
