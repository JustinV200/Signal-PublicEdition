# console web

The front end of the Signal console: a radar-styled HUD onto the Claude Code orchestrator. A scope with the live state lands first; chat, voice, boards, tasks and system are tabs beside it, with a Setup tab while a picked tool is unfinished or Setup is open, and a status line above and an input line below. The spec is `DESIGN.md`.

Everything the page does goes through the backend in `tools/console/src`: typing sends `POST /api/send`, every button and palette command sends `POST /api/action`, and the page only reads state from `GET /api/state`, the `GET /api/events` stream (including the `tasks` event), `GET /api/devices` and the camera stream `GET /api/camera/stream`. System's Away/Here toggle calls `POST /api/away` and its model pickers `POST /api/models`. Setup and System's tools list run the setup CLI through `POST /api/setup/run` (streamed) and `POST /api/setup/terminal`. Typed messages go to Claude; buttons don't: the console server runs each one itself, so a button reads "Working…" and its action row in Chat goes working, then done with what happened (or failed with why). All server text is rendered as React elements; nothing touches `innerHTML`.

The page keeps itself current: the server pushes every change on the stream (a keepalive every 5 s when idle), the page reopens a stream that goes 20 s without a byte, and it re-reads everything when the window becomes visible again or the network returns. When the stream goes quiet or the server stops answering, the status line says so (`no update for 25s`) beside a Refresh button that re-reads now; while all is well neither shows, and `Refresh` in Commands does the same. After a server restart the page stays signed in (the server keeps a digest of each window's token on disk) and reconnects on its own; `console open` is needed again only for a window older than the newest 8 logins.

## Commands

Node 24. From this folder:

- `npm install` once.
- `npm run build`: type-check, then write `dist/`, which the Python backend serves as static files.
- `npm test`: Vitest (markdown URL policy, reducer dedupe, 401 handling with the server's reason, the server-down wording, board rows and their preview buttons, action progress from deliveries, the camera's MJPEG reader, the Tasks page's words, the event stream's stall reconnect and resync, the status line's connection words, the setup CLI's JSON in its output, settings schema to form fields, where the wizard resumes and that it stays on its page when a step finishes, the wizard strip's sections, the wizard's page and typed values across a view switch, the tour following a tab click, tool health words, a Button's `quietReason`: tooltip, no caption, the setup wizard's one running state and its busy wording, the consent page's split of `setup plan` (plain lines and exact entries; a failed plan is an error, never consent)).
- `npm run lint` (also refuses a UTF-8 BOM), `npm run format`.
- `npm run mock`: the fake backend on `127.0.0.1:8790` (`dev/mock-server.mjs`). That is the real console's port, so screen checks run it elsewhere: `npm run mock -- --static dist --port 8795`, then open `http://127.0.0.1:8795/#k=dev`. `--static dist` also serves the build, `--old-whiteboard` reports the whiteboard on with no view (the to-do button is then disabled), `--whiteboard-off` reports it off (no saves listed, every button on), `--night` starts in sleep mode's night view (Realign whiteboard and Full calibrate off, the reason said once; the preview's caption says boards sent stay hidden, and a board sent keeps the view at `night`, as the whiteboard does), `--many-saves` adds 24 plain saves so the list outgrows the view (the sticky preview), `--setup-fail` makes `setup list` and `setup status` fail like a broken progress file (the Setup page's and System's tools list's error states; the Setup tab then hides, since the picks are unknown), `--setup-fresh` starts setup as a fresh checkout leaves it (nothing picked, only the console built, so the wizard opens on Welcome and there is no Setup tab until Setup is opened; the usual mock data has unfinished picks, so the tab shows), `--setup-done` starts with every pick finished (no Setup tab until Setup is opened), `--setup-all` starts with every tool picked, mid-setup (the wizard's strip, its tools list beside a tool page and the console tour with every tool tab), `--claude none|closed|quiet|unknown` starts the Claude session never claimed, claimed but closed, quiet for 12 min or with no hook yet (the status line's states; without it the session is linked and idle), `--health port|hooks|ok` picks the console's own checks (`GET /api/health`, `dev/mock-health.mjs`): `port` (the default) has another checkout's console holding the port, the case with that checkout's path in its row; `hooks` has the turn and session hooks missing, so `--claude unknown --health hooks` shows `state unknown · turn hook missing` and Models' pointer to the Console row; `ok` passes everything (the claim and whiteboard rows follow `--claude` and `--whiteboard-off`), `--empty-chat` seeds no history, so Chat and Voice open on their empty states (the seeded history otherwise has two action rows back to back and a long reply with paragraphs, two h2s, an ASCII table in a code block and a markdown table, for the chat's rhythm and table alignment), `--empty-lists` lists no saved boards and no tasks (the Boards and Tasks empty states), and `--news-every 15` lands a live unprompted Claude reply or a console note (in turn) every 15 s, so the Chat tab's `2 new` and the window title's count rise while another view is open (`dev/mock-seed.mjs`). Stop the mock to see the server-down words, and wait 20 s for `no update for 25s`; or pass `--down-after 20`, which makes the mock stop answering 20 s after it starts, for 60 s (open the page before then: 10 s into the outage the server-down notice shows, with the open command). Open `#k=bad` for the signed-out page (the bad-key reason and the open command). The 401 bodies, the made-up open command and the outage switch are in `dev/session/mock-session.mjs`. Each button's echo and done words are in `dev/actions/mock-actions.mjs`, and a board button's effect on the state in `dev/actions/mock-board.mjs`. The starting state is built in `dev/mock-state.mjs`, the tasks and device data come from `dev/mock-pages.mjs` (its camera always answers "2 viewers already"), the models from `dev/mock-models.mjs`.
  - Setup and System's tools list: `dev/setup/mock-setup.mjs` answers `POST /api/setup/run` like the real route (400 for a bad shape, 409 while a writing command runs, NDJSON lines then the exit code) and `POST /api/setup/terminal` (checks the tool and step ids, then ok; nothing opens). `dev/setup/mock-setup-cli.mjs` prints what `intro`, `list`, `prereqs`, `plan`, `status`, `tour`, `apply`, `auto`, `choose`, `mark`, `wire`, `config`, `samples` and `doc` print, from the neutral registry in `dev/setup/mock-setup-data.mjs` (its entries built by `dev/setup/mock-setup-entries.mjs`, as `setup list` prints them today: the console's install, web-deps, web-build, logon and claim steps): eleven tools mid-setup, every step kind and status, each with its Pick tools group and cost tag (the vault's install is left to do, so its `Run the automatic steps` shows, and its init failed). `status` (`dev/setup/mock-setup-checks.mjs`) gives each tool's `words`, `fix` and `command` as `setup status --json` does: Gmail is set up but its `mail check` fails with a fix and a command (so its `Fix` opens a tool page whose steps all read done, under the check's banner), Voice's `audiohub check` passes with a fix (the hub isn't running), and the brief's check timed out. `auto` (`dev/setup/mock-setup-auto.mjs`) runs the picks' automatic steps with the same fake runs and streams slowly like `apply`; with `--setup-fresh`, pick a few tools and `Save N picks and install` shows the whole batch. `--setup-done` starts from `dev/setup/mock-setup-entries.mjs`'s `withPicksDone`, which marks every step of every pick done, and `--setup-all` from its `withAllPicked`, which picks every tool and keeps its progress. The browser's settings (`dev/setup/mock-setup-config.mjs`) have one row per type, one advanced row and the placeholder `example_setting`; saving a real value there finishes its settings step. Samples (`dev/setup/mock-setup-samples.mjs`) start at 3 saved, and "From my sent mail" lists two made-up mails. `doc` (`dev/setup/mock-setup-doc.mjs`) answers every step that names a guide with one short made-up guide (a link, code, and raw HTML that must stay text), except copytone's, which reads as a guide this copy doesn't ship. `plan` (`dev/setup/mock-setup-plan.mjs`) gives each finished tool its plain consent line (the registry's words; the browser, whose mock adds no rules, reads `asks you each time`), a blank line, then the exact entries. `verify` isn't mocked (it fails with a line saying so). Clicks change the mock's progress until it restarts.
  - `apply` streams a line every 250 ms. Most steps end done; the browser's Docker step fails (Docker Desktop is the mock's missing program); Gmail's sign-in needs input until the address step is saved; a terminal or samples step answers "needs your terminal" (exit 3).
- `npm run dev`: Vite with `/api` proxied to the mock. The real backend refuses proxied requests (Vite's Host/Origin), so test against it through `dist/`.

## Layout

```
src/
  main.tsx       fonts, styles, theme, render
  app/           App (session gate), Shell (status + view + input), SignIn (401), the server-down notice, the open command with Copy
  api/           wire types, parse checks, fetch client, SSE with backoff
  state/         reducer, dedupe, board rows and view words, whether Claude is linked, session start, store
  state/actions  optimistic sending, action labels, action progress and the pending set
  status/        status line: connection words, freshness and Refresh (only when stale or offline), the tab row (arrow keys), help button, phase dot
  models/        the model strip for System: now / next-session pickers, voice's pickers
  help/          the help panel (what each view does, shortcuts) and the console tour bar
  ui/            the shared Button (hover/press/focus, pending, disabled with a reason), the one Copy control, page visibility
  empty/         the one empty state of Chat, Voice, Boards and Tasks: dashed ring, HUD label, one line
  views/scope    the radar: blips and readout from the live state, the SVG scope
  views/chat     message stream, working row, dividers, the claim help while no Claude session is linked
  views/voice    voice state, Start/Stop buttons and the feed
  views/boards   board list, preview panel, Send to projector, Show live version, Show saved copy, Realign and Full calibrate
  views/tasks    the orchestrator's task list and the usage line
  views/system   the System page: you, console, tools, devices, models, appearance
  views/devices  the devices poll, device rows, the camera view and the Away/Here toggle (for System)
  views/setup    the setup wizard: screens, steps, settings forms, samples, live output; tool health and the Setup tab rule
  input/         input line, history recall, auto-grow, confirm line
  palette/       Ctrl+K commands, filter, list
  keys/          global shortcuts
  markdown/      react-markdown with http(s)-only links and no raw HTML
  scroll/        auto-follow and the "N new" pill
  time/          clock formats and the shared ticker
  styles/        tokens (both themes; the only file with literal colours), base (the 132ch frame, the 96ch reading column, .view, .view-header, .panel), motion
tests/           mirrors src/
dev/             mock backend (not bundled)
```

Each `src/` folder has a `README.md` and an `index.ts`; folders import each other only through `index.ts`.
