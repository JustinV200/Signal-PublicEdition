# setup_cli

The setup wizard's bridge to `tools/setup` (the console's Setup tab and System's Tools list). It runs the setup CLI as a program (`uv run --project tools/setup --frozen --quiet setup ...`), never imports it, so the tools stay standalone and the CLI stays the single source of truth for tools, steps, settings and progress.

- `requests.py`: `build_call(body)` turns `{command, ...}` from the page into fixed CLI arguments. Commands: `intro`, `list`, `plan`, `status` (`--json` health), `tour` (`--json`), `wire` (`--yes`), `prereqs`, `choose`, `auto` (the picks' automatic steps, or just the named tools'), `apply`, `mark`, `config` (`--list`, or `--set`), `samples`, `doc` (a step's guide, by tool and step id; the CLI opens only the file its registry names). `verify` is refused: its rows carry a failing check's raw output, which the page has no use for (it reads health from `status --json`). Ids are checked by shape and never start with `-`; free text goes as `--flag=value` or on stdin (pasted samples).
- `runner.py`: `SetupRunner` runs one command at a time (a second gets `SetupBusy`, a 409) with stdout and stderr merged and unbuffered, handing each line on as it comes. A page that goes away doesn't stop the command.
- `terminal.py`: `open_terminal(root, tool, step)` opens a PowerShell window on `setup.ps1 step <tool> <step>`, for steps that need the owner's own terminal (passwords, Windows Hello, typed client IDs). It runs that one step and wires nothing; the secret is typed there, never through the page or the server. Both ids are checked by shape, and the setup CLI refuses one its registry lacks (exit 2) before anything runs. `-NoExit` keeps the window open after the script's `exit`, so the result stays readable.

Depends on `signal_console.launch` (clean environment). Used by `server/routes/setup.py`.
