# orchestrator

Which Claude Code session the console talks to, and how it talks to it.

- `claim.py`: `write_claim` and `read_claim` place the claim at `.state/orchestrator.json` (owner-only). Building, encoding and checking a claim is the shared `signal_orchestrator` package's job (`packages/orchestrator`): `claim_from_env` and `read_claim_file` refuse a socket that isn't a local named pipe (`\\.\pipe\...` with no `..` or `/`), since the token is written to it. The voice hub reads the same file to hand jobs off.
- `liveness.py`: `is_claim_alive(claim)` is True while the claimed session's inbox pipe is listed under `\\.\pipe\` (a session's pipe exists only while it runs). It only looks the name up, never connects, so nothing reaches the session; no claim is not alive, and a listing that fails (not Windows) counts as closed with a warning. About 1 ms per call. The status watcher publishes it as `orchestrator.alive`; the doctor is meant to reuse it. `claim_pipe_listed(claim)` is the same lookup but returns None when the listing fails, for the auto-claim.
- `auto_claim.py`: `claim_if_free(state_dir, environ, now)`, run by `console tasks set`: when there is no claim or its session has closed, it claims for the caller's inbox variables through `write_claim` (so the watcher notes the takeover) and returns the new claim. A live claim is never replaced, nor one whose session can't be checked (the pipe listing fails); no inbox variables (a plain terminal) claims nothing. Subagents share their parent's process and inbox variables, so a subagent claims for its parent session.
- `claim_words.py`: `default_label(now)`, the label for a claim made without one (its local time, `Tue 17 Nov 10:25`), and `claimed_ago(claimed_at, now)` (`linked 26 days ago`, the page's word for a claim; None for a time that isn't ISO with an offset), used by the watcher's claim note and the doctor's claim row.
- `send_to_inbox(claim, text)` (from `signal_orchestrator`) writes the auth line and the message frame to the session's named pipe, and raises `InboxError` if that fails. The frame format isn't documented; see that package's `inbox.py`.
- `messages.py`: `chat_request` turns typed text into `ConsoleRequest(display_text, orchestrator_text)`, with the `[Signal console]` marker and the owner's name (`owner.py`: `SIGNAL_OWNER_NAME` from `.env`, else `the owner`). The marker is a label, not proof of consent: anything holding the session's inbox token can write it. Buttons never reach the orchestrator; the server runs them itself (`signal_console.actions`).

Public API: `signal_console.orchestrator` (`write_claim`, `read_claim`, `is_claim_alive`, `claim_if_free`, `default_label`, `claimed_ago`, `chat_request`), which re-exports `Claim`, `ClaimError`, `SOCKET_ENV`, `claim_from_env`, `InboxError`, `encode_frames` and `send_to_inbox` from `signal_orchestrator`. Depends on `signal_orchestrator`, `state_files`, `owner` and `paths`.
