# browser_tool.actions

One async function per MCP tool. Each takes an `ActionContext` and returns the text the model sees, or raises `ActionError` with a message we wrote ourselves.

## Public API (`from browser_tool.actions import ...`)

- `ActionContext.create(settings, confirmer, filler, backend=None, *, allow_relaunch=True, holds_dialogs=True)` builds the policy, the action rules and an idle `BrowserSession`. Tests construct it with fakes.
  - `allow_relaunch=False` (visit mode) makes every action after the browser closed fail with `BrowserClosedError` instead of relaunching Edge.
  - `holds_dialogs=False` (visit mode) dismisses every page dialog instead of holding it for `answer_dialog`.
  - `uploads_allowed` and `downloads_readable` are False on the docker server, so `upload_file` and `read_download` refuse. `secret_values` keeps each tab's secret values as last read, for the scrub of a tab a dialog freezes.
  - `backend` is where Edge runs (default: the desktop profile). A backend's guest block goes into the policy (docker jobs).
  - `password_field_refusal` is what `type_text` and `press_key` say in a secret field: `PASSWORD_FIELD_REFUSAL` (points at `fill_login`) by default, `NO_VAULT_PASSWORD_REFUSAL` on the docker server, which has no vault.
  - `has_vault` is False on the docker server, so the signed-out note doesn't point at `fill_login`.
  - `config_name` is the config file navigate's allowlist hint names (`--config`, else `browser.toml`, or `browser-docker.toml` on the docker server).
- Navigation:
  - `navigate(ctx, url)`
    - It checks the policy before loading and adds `https://` when no scheme is given.
    - It refuses non-http(s) URLs and URLs with embedded credentials.
    - It reports blocked redirect hops.
    - If the tab still lands on a non-allowed origin, it clears the tab.
    - A URL that starts a download returns "<url> started a download" instead of failing (Playwright fails `goto` with "Download is starting"; it waits up to 5 s for the download event).
  - `back(ctx)`, `forward(ctx)` and `reload(ctx)` (`navigation/history.py`). A step that didn't move the tab says "no previous page" or "no next page"; a hash-only step counts as a move. One that turns into a download or hits a blocked hop is described like navigate's. Edge silently sends a form's POST again when a step lands on a page a form submitted to, so each step runs inside a `ResubmitGuard` that aborts a main-frame POST (ERR_ABORTED, so the tab stays put); the step then runs the send rule ("it would send a form again") and steps again only on an Allow, with `ensure_ready_to_act` right before it (or after a log line, when send isn't in `always_confirm`). `reload` refuses a Duo tab first, since reloading the prompt sends a new push.
  - `list_tabs(ctx)`, `switch_tab(ctx, index)`, `new_tab(ctx, url)` (the URL goes through navigate's checks before any tab opens, then loads through `navigate`) and `close_tab(ctx, index)` (refuses the only tab).
  - navigate and the history steps share `signin.report_location`: the landing backstop, block notes and the signed-out note.
  - Settling (`navigation.NavigationWatch`): navigate, back, click and press_key run inside a watch that records the tab's main-frame navigation requests and `framenavigated` events. With neither, the result comes back at once. With one, it waits for the navigation to commit (or fail, or turn into a download), then for `load`, then for 0.25 s with no new main-frame navigation request (each new one restarts the wait), at most the navigation timeout. Playwright's click waits for a navigation it set off to start, but a key press doesn't, so press_key (any key but the free ones) first gives a navigation 0.2 s to start, ended early by the first request. Read only.
- Dialogs and uploads:
  - `answer_dialog(ctx, accept, text=None)` (`dialogs/answer.py`) answers the confirm, prompt or beforeunload that freezes the current tab (`session.DialogWatch` holds it). Duo lockout first; accepting runs the text rules on the message plus the texts of the action that opened it (its trigger: the clicked label, the pressed key and its form; `act_and_report(trigger=...)`), so "Delete 3 messages?", or "Are you sure?" after clicking "Remove draft", asks as a delete; dismissing never asks. Right before answering, the dialog must still be the one judged, then `ensure_ready_to_act`. `text` only goes with `accept=True` on a prompt, at most 1000 characters, and is refused for a prompt whose message asks for a password, passcode, PIN or code. Neither text nor message is ever logged.
  - `dialog_notes(ctx)` (`dialogs/notes.py`): what the tool runner adds to every result: alerts accepted since the last result, file pickers a page opened by itself (dropped), and each open dialog with how to answer it, page text in `<untrusted_page_content>` on one line.
  - `upload_file(ctx, ref, path)` (`uploads/upload.py`): refused when `ctx.uploads_allowed` is False (the docker server). The ref is prepared like a click's (Duo first). The file is checked and read once (`local_files.read_checked_file`: a plain drive path, no link or junction on any part (lstat from the drive root down, before resolving), resolves to itself with no short name, inside `[uploads] roots`, not the vault's folder, `.profile*`, `.state`, `.env*`, `*.env` or a key file, a regular file with one hard link, at most `[uploads] max_mb`, and the opened file is the one checked). The gate is always the send rule plus the text rules (a file input) or the whole click rule (an upload button it clicks); the dialog names the file and size. Right before acting it is judged again (stricter, or no longer the same kind of element, is refused), then `ensure_ready_to_act`. A file input gets the bytes through `set_input_files`; a button is clicked and the picker it opens (claimed from `session.FileChooserWatch`, within 5 s) gets them, after another `ensure_ready_to_act`.
  - While a dialog is open on a tab, `guards.ensure_page_allowed` (run by every action and read tool, and inside `ensure_ready_to_act`), `navigate` and the history steps refuse that tab with `DIALOG_OPEN_REFUSAL`, since its evaluate, click and press would never return. `act_and_report`, `type_text`, `select_option`, `hover` and `scroll` run their page action through `pointer.act_checked` (`ensure_ready_to_act` then the action, in one task) and `session.act_until_dialog`: when the action opens a dialog, they stop waiting, leave it to finish once the dialog is answered, and say "it opened a dialog". The settle runs through `session.read_until_dialog` and is cancelled by one. The signed-out note is skipped on a tab with a dialog. `scrub_secrets` reads each tab through `read_until_dialog` and, for a tab a dialog freezes, uses its values as last read (`ctx.secret_values`).
- Page content:
  - `snapshot(ctx, ref=None, page=1)` returns one page of a redacted aria snapshot with refs, wrapped in `<untrusted_page_content>`, then `page N of M`. Pages are `[browser] max_snapshot_chars` long, cut at line boundaries. The plain call takes a fresh snapshot and caches its redacted text, title and shown URL for the tab, after scrubbing every tab's live secret values and the vault's fills out of both (`scrub_secrets`, the same scrub the tool runner uses; a failed scrub refuses and caches nothing) (`ctx.snapshots`, `snapshot_cache.SnapshotCache`); `page=N` and `ref=eN` (that element's line and everything indented under it) are served from the cache, or from a fresh snapshot when there is none. The cache is per tab, replaced by each fresh snapshot and dropped when the tab's main frame navigates (and ignored if the URL changed anyway).
  - `find(ctx, text, max_results=20)` searches the same cached redacted text, case-insensitively: each match gives its line, page, ref (its own, else the nearest ancestor's) and up to four ancestor labels, in `<untrusted_page_content>`, then how many lines matched. The query is never echoed. `max_results` is capped at 100.
  - `wait_for(ctx, text=None, gone_ref=None, url_contains=None, network_idle=False, timeout_s=10)` waits, read only, until every given condition holds (text in a fresh snapshot, polled every 0.25 s; snapshots are redacted and scrubbed, never the live DOM, so it can't confirm a secret mirrored into page text; the ref's element gone or hidden, the URL without query or fragment, scrubbed the same way and polled, containing the string, network idle), `timeout_s` capped at 30. It answers "waited N s for: ...; now at <url>" or "still waiting after N s for: <unmet>; now at <url>", both through `report_location` (so a blocked landing is cleared either way), and scrubs its result (`scrub_or_refuse`). It never returns page text. The polled conditions stop as not met once the tab is on an origin the policy doesn't allow. If one condition raises, the others are cancelled and awaited.
  - `screenshot(ctx, ref=None, full_page=False)` saves a PNG of the viewport, the whole page or one element, sensitive fields masked in every frame, and returns only its path. It refuses a Duo tab first, then a dialog or refused page, then filled credentials.
  - All four refuse with `FILLED_CREDENTIALS_MESSAGE` while the vault reports filled fields. `find` and `wait_for` refuse a Duo tab first, before the origin check.
- Interaction:
  - `click(ctx, ref, button="left", double=False, modifiers=())`, `select_option(ctx, ref, value)` and `press_key(ctx, key)` go through the gate rules. `type_text` does too, but only for its frame. Every click variant is gated like a plain click. A double click is two halves: the first click at the centre of the element's box, then the click rules again (refusing one that now asks more), a hit test at that point (the element there must be the ref's element or inside it, through shadow roots and iframes), and a second press with `click_count=2`. A refused second half says the first click ran.
  - `click_at(ctx, x, y)` gates on the deepest element at the viewport point, found through open shadow roots and into iframes (each frame checked: blocked refused, opaque unverified), without scrolling. A frame it can't see into (or frames nested past 5) makes it gate on the `<iframe>` with the unverified-frame rule. Right before the mouse click it looks again and refuses ("the page changed under that point") if another element is there.
  - `drag(ctx, source, target)` runs the click rules on both ends and keeps the strictest, then `drag_to`.
  - `hover(ctx, ref)` and `scroll(ctx, ref=None, direction="down", amount=1)` never ask (`gating.log_only`), but run the Duo, origin and frame checks and `ensure_ready_to_act`. scroll moves the nearest scrollable box (the ref, an ancestor, or the page) by `amount` screens (up to 10) and reports the visible range in px; when it reaches the end it waits up to 1 s and says if the content grew.
  - `type_text(ctx, ref, text, append=False, slowly=False)` refuses password and OTP fields with `ctx.password_field_refusal`, unless `[gates] allow_secret_fields` is on (the job runner's dedicated accounts; the value is still never logged and stays redacted and scrubbed). In those fields `press_key` allows only navigation keys. `append` adds at the end (the field must take focus, or it refuses); `slowly` types key by key. Neither ever presses Enter or Tab: other control characters are inserted as text, and line breaks go in through the DOM (a textarea's `setRangeText`, `insertLineBreak` in a contenteditable) and are dropped in a single-line input, because Edge submits a single-field form even on an inserted line break.
  - `select_option(ctx, ref, value)` takes one value or a list (a multi-select) and gates on every option it picks.
  - Page-supplied labels in results are wrapped in `<untrusted_page_content>`.
- Credentials:
  - `list_credentials(ctx)` lists the credentials.
  - `fill_login(ctx, credential_id, submit)` returns only `ok`, `failed: <code>` or `vault not installed`. It refuses with `LOGIN_LOOP_REFUSAL` once the site's two fills in 10 minutes are used (below).
- Sign-ins (`signin/`):
  - `wait_for_duo(ctx, timeout_s=90, wait_anyway=False)`, read only: never a click, key, fill or script in the page. Not in Duo: `no Duo prompt on this tab`. Otherwise it reads the prompt's voice ping outcome (`DuoWatch.ping_outcome`, about 8 s at most). Heads-ups ring through sleep and away, so a current hub speaks them; a ping dropped anyway (a hub without ring-through) returns at once with the reason and "the push is still on the phone; call wait_for_duo again later or move on", unless `wait_anyway`. Then it waits (`duo.wait_until_off_duo`, `timeout_s` capped at 300), lets the landing settle (`duo.wait_for_settle`: load, then about 1 s with no main-frame navigation, at most 10 s) and returns "Duo approved; now at <url>" through `report_location`, the timeout text with the ping line, or `the tab closed`. A `timeout_s` not above 0 is an `ActionError`.
  - The signed-out note: `navigate`, the history steps, `new_tab`, `click`, `click_at`, `drag` and `press_key` let the landing settle when they navigated the main frame (`navigation.NavigationWatch`, above), `wait_for` reports wherever the tab is, and `wait_for_duo` settles for up to 10 s. If the main frame then shows a visible `input[type=password]`, the result ends with "signed out: this is <site>'s login page. If you have a credential for it, fill_login(id, submit=true) once, then wait_for_duo if Duo appears." (with `has_vault=False`: "no saved logins; tell the owner"). `<site>` is the hostname or its `[duo] site_names` name (`duo.shown_site`).
  - The login loop: `ctx.session.login_loop` counts ok fills per site. A login plus one retry are allowed; a third `fill_login` on the same site within 10 minutes is refused with `LOGIN_LOOP_REFUSAL` ("... asked to sign in again right after a login. Stop and tell the owner"), and the signed-out note says "login loop" instead of suggesting a fill. It only ever refuses; it never fills.
- Downloads: `download_notes(ctx, started_before)` waits up to 60 s for the downloads started since `started_before` (the call's own) and returns one note per finished one: `download saved (N bytes): ` plus the original name and saved path in `<untrusted_page_content>`, or `download not saved: <why>: ` plus the name. The tool runner adds them to every result, because a click's download can start just after the click returns (it is then reported with the next tool result).
- `read_download(ctx, path, pages=None)` (`downloads/read_download.py`): refused when `ctx.downloads_readable` is False. The path goes through `local_files.read_checked_file` with the downloads folder as the only root (50 MB cap). `.pdf` text comes from `downloads/pdf_text.py`, which runs `pdf_worker.py` (pypdf) in a child process (`python -I`) with a 20 s limit (the child also stops itself) and checks its JSON reply; at most 20 pages per call. `.txt`, `.csv`, `.md`, `.json` and `.log` must be UTF-8 with no NUL. The whole text (and the file name) is put through `scrub_or_refuse` first, then cut at `max_snapshot_chars`, then wrapped as untrusted, so a cut can't leave half a secret. The child's reply is read up to 8 MB and each page's text is capped in the child.
- `describe_playwright_error(error)` maps a Playwright exception to a generic reason. Raw Playwright text can contain `fill("<value>")`.

## Gating and origin rules

- Duo lockout: while the current tab is in Duo (`ctx.session.duo.is_in_duo`), `click`, `click_at`, `drag`, `hover`, `scroll`, `type_text`, `select_option`, `press_key`, `reload`, `answer_dialog`, `upload_file`, `screenshot` and `fill_login` refuse with `DUO_LOCKOUT_MESSAGE` before anything else. Only the owner answers Duo. `navigate`, `back`, `forward`, `switch_tab`, `new_tab`, `close_tab`, `snapshot` and `tabs` still work; `find` and `wait_for` refuse too.
- The page must be on an allowed origin.
- Right before the click, drag, hover, scroll, fill, select or key press (and an approved form resubmission), `ensure_ready_to_act` checks again, with no await in between: not in Duo, still on an allowed origin, and, for an action the owner approved, still on the origin the dialog showed (`confirm_or_log` returns it). When the tab left that origin, the refusal starts with `TAB_MOVED_REFUSAL`. An owner dialog can wait long enough for the tab to redirect to Duo or another site, and `press_key` has no element to pin it to a page.
- `fill_login` checks Duo and the policy only at the start. The vault asks the owner itself and then re-checks the page's and fields' origins on its own element handles right before it fills, so a tab that moved meanwhile isn't filled. TODO: a Duo iframe added to the page meanwhile isn't caught; that needs a pre-fill hook in the vault.
- An element in an `about:blank`, `about:srcdoc`, `data:` or `blob:` frame is an origin mismatch. Acting on it is logged (see below).
- An element in a frame from a blocked host is refused.
- Every gate rule (in `gating/`) returns a `GateCheck` (`browser_tool.gates`). `gating.confirm_or_log` asks the owner through the `Confirmer` when the rule's category is in `[gates] always_confirm`, and otherwise lets the action run and logs one INFO line: the tool, the ref and role or key name, the origin and the reason, never page text or typed text. The rules:
  - purchase, send and delete: a click whose snapshot label or live text matches the category's patterns (`browser_tool.config.CATEGORY_PATTERNS`), or one of the owner's `[gates] patterns`, which always ask
  - send: a click on a submit control in a form that isn't a search form (inside `<search>` or `role=search`, or with one search field as its only text field; a `role=combobox` or `name=q` field counts only as an `<input>`), or an explicit GET form (`method="get"`, or the button's `formmethod`), unless it is a sign-in submit (below) or its text starts with "Save draft" or "Save as draft". Other "Save" buttons ask: Moodle's "Save changes" can hand an assignment in.
    - A sign-in submit: its own form (including via `form=`) has a visible, filled password field (only the value's length is read), no textarea, contenteditable, file field or custom element (which may hide an editor in its shadow DOM), and at most two other rendered text fields; and its whole label is sign-in wording (log in, login, sign in, signin, sign on, log on, next, continue or verify, any case, with optional trailing arrows or punctuation; `config.SIGN_IN_WORDING_RE`). Visible means rendered, bigger than 1x1 px, on the page, drawn at 0.1 opacity or more, not cut away by a clip-path, clip or 1px overflow-hidden ancestor (across shadow hosts), and found by a hit test at its centre. For Enter, the label is that of the form's default submit button; an implicit submission with no button has none, so it asks.
  - click rules run on the element hit at the click point (found through shadow roots) and on every ancestor of it and of the target, across shadow hosts, plus a clicked `<label>`'s control. Clicks bubble, so any ancestor's handler can fire.
    - Every ancestor contributes its aria-label, aria-labelledby, title and alt.
    - Interactive ancestors (links, form controls, `[onclick]`, `[tabindex]`, widget roles, `cursor:pointer`) also contribute their text and their descendants' alt and aria-label.
    - A click that would land in an `<iframe>` counts as an unverified frame (logged).
  - `press_key`: paste keys (Control or Meta+V, also with Shift, and Shift+Insert) are refused, because they would type the owner's real clipboard. Tab, Shift+Tab and Escape are free. The arrows, Home, End, PageUp and PageDown are free when focus is not on a form control, an ARIA widget, or a custom element that may hide a closed shadow root (see `browser_tool.gates.key_kind`). Other keys go through the rules, on the focused element (found through open shadow roots) and its form's submit controls:
    - the pattern rules on their text
    - Enter, or Space on a submit control: send when it submits a form the click rule would ask for (the search, GET and save-draft exceptions as above). Enter from any non-button input, checkbox and radio included, presses the form's first submit control. That includes Enter in a form's only text input when the form has no submit button (implicit submission).
    - Enter with Control or Meta: send wherever focus is (nothing focused included), unless it is in a search box or search form. This applies on `[gates] no_confirm_origins` too.
    - Enter in a textarea or contenteditable that isn't in a search box or search form: send, except on `[gates] no_confirm_origins`. A search box is `<search>`, `role=search`, `role=searchbox` or `type=search`; a `role=combobox` (an @-mention composer is one) counts only as an `<input>` that is a search form's single field.
    - the Delete key: delete
    - anything else is logged, except on `[gates] no_confirm_origins`
  - a select whose live name, or live option label or value, matches. The name comes from `aria-label`, `aria-labelledby`, its labels and `title`. A `<label>` is followed to its control. Anything that isn't a `<select>`, or a value with no matching option, is refused.
- A decline, a timeout or a dialog failure all mean no.

## Files

- `context.py`: `ActionContext`, `RefLabels` and the two password-field refusals.
- `errors.py`: `ActionError` (defined in `browser_tool/errors.py`, below every subpackage, so the session can raise one too) and the Playwright error mapping.
- `guards.py`: the Duo lockout, page-origin, last-moment, filled-credential, ref and frame checks, plus block notes.
- `untrusted.py`: `wrap_untrusted` and the `<untrusted_page_content>` tags.
- `snapshot_cache.py`: `SnapshotCache`, each tab's latest redacted snapshot.
- `secret_scrub.py`: `scrub_secrets(ctx, texts)`, the shared scrub over every tab's live secret values and the vault's fills, and `scrub_or_refuse`, its fail-closed form for the read tools. `shown_url(ctx, url)` is the one form every result shows a URL in, and the form `wait_for` matches: origin plus path, scrubbed, then percent-decoded (control characters replaced) and scrubbed again, so a secret holding its own `%XX` and one Edge encoded are both caught. `navigate`, `back`, `tabs` and `switch_tab` show URLs this way too. If the scrub fails, it falls back to the origin.
- `gating/`: the gate rules for clicks, selects and keys, and asking the owner or logging (see its README).
- `navigation/`: `navigate` (`navigate.py`), `back`, `forward` and `reload` (`history.py`, with `resubmit_guard.py` and `load_failure.py`), `tabs`, `switch_tab`, `new_tab` and `close_tab` (`tabs.py`), and `NavigationWatch` (`nav_watch.py`).
- `page/`: `snapshot`, `find`, `wait_for` and `screenshot`, one file each, plus the pure paging and search helpers (`paging.py`).
- `pointer/`: `click` (`clicks.py`), `click_at`, `drag`, `hover` and `scroll` (`passive.py`), `type_text` and `select_option` (`fields.py`), `press_key` (`keys.py`), their shared prelude (`target.py`) and their last-moment check and result (`after_action.py`).
- `dialogs/`: `answer_dialog` (`answer.py`) and `dialog_notes` (`notes.py`).
- `uploads/`: `upload_file` (`upload.py`).
- `local_files/`: the pure local-file check `read_checked_file` (`checked_read.py`), shared by `upload_file` and `read_download`.
- `login.py`: the credential tools.
- `downloads/`: the download notes the tool runner adds to every result (`notes.py`) and `read_download` (`read_download.py`, `pdf_text.py`, `pdf_worker.py`).
- `signin/`: `wait_for_duo` (`duo_wait.py`), `report_location` (`landing.py`), and the signed-out note and login-loop refusal (`login_note.py`).

## Dependencies

`playwright`, plus browser_tool `config`, `policy`, `redaction`, `gates`, `credentials`, `session` (including its dialog watch), `duo` and (through `session.downloads`) `downloads`; and `pypdf`, only inside the `pdf_worker.py` child process.
