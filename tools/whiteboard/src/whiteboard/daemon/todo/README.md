# whiteboard.daemon.todo

The TODO view inside the running daemon.

## Public API

- `TodoController(board, TodoFiles(life_dir, state_path, audit_path, keynotes_path=None), clock=datetime.now)` (`TodoFiles` in `files.py`):
  - `start()`: first sync at daemon start (a broken `life/` is logged, not fatal).
  - `sync()`: re-read this and next week's plans and today's keynotes (`keynotes.read_keynotes`; none when stale or missing), track changes, lay out for the current board size, push to the page. Returns the summary below.
  - `show()` / `hide()`: switch the scene's view to `todo` (then sync, so new ticks animate on screen) or back to `items`. Under the night view they only change the view it goes back to, and the reply's `view` says `night`. A `show()` that puts the view up calls `on_shown()` (a no-op until the daemon sets it to `StrikeWatcher.note_view_shown`).
  - `set_done(ref, is_done, source, by_text=True)`: re-read the plans, find the item (`by_text=False`, used for cross-outs, accepts only an exact id), tick or untick every line of it with `set_line_done`, log it to `.state/todo.log` (`audit.py`), then sync. It syncs even when a later line of the item fails to write, so the page shows what was written. A line edited since the last sync is still found while its tag and text (the id) are the same.
  - `mark_struck(ids)`, `add_hints(ids)`: what a board cross-out does when it's sure / unsure. An item `mark_struck` can't tick (its line changed meanwhile) gets the hint instead. Hints show `done?` until the item is done or the day ends.
  - `layout_generation`: goes up whenever the rows on the page move or change (`strike_rows.row_spots`: each row's item, due text and box), and whenever `show()` switches the page to this view. Ticking an item moves no row, so it doesn't count.
  - `strike_targets(generation)`: the open rows as `StrikeTarget`s (`strike_rows.open_targets`: each row's box, its text as shown, `[tag] text (due ...)`, the rows just above and below it in its column, and `has_twin` when one of those has the same item text), or `[]` if the view isn't showing or isn't at `generation` any more. It's re-laid out first if the board size changed, which is a new generation.
  - One lock keeps syncs and edits in order.
- `add_todo_routes(app, controller)`: `POST /api/todo/sync|show|hide`, and `POST /api/todo/done|undone {item}`. 404 for no or several matches, 409 when the plan changed during the edit (the line is gone or now there twice, or the file changed before the write) or can't be written, 503 when `life/` can't be read, 400 for a bad body. Behind the daemon's token guard like every `/api/*` route.
- `StrikeWatcher(todo, rig, confirm, forward, StrikeHooks(note_snapshot, is_drifted))`: the change watcher's callback, in front of the board agent. With each snapshot it records the rig's calibration, whether the TODO view showed, and its `layout_generation`. A change is only checked when the view showed at the same generation, under the same calibration object, at both this snapshot and the previous one, so the ink between them was drawn over the rows it's matched against; and only when `is_drifted()` (the drift monitor's latest check that found the board's outline, usually this capture's, `DriftMonitor.is_drifted`) is false. Anything else goes straight on: a re-align or new fit, a sync or re-fit that moved rows (including from another session), a switch into the view, or a camera bump not yet re-aligned for. `note_view_shown()` takes a fresh clean capture (`camera.clean_capture`) as the "before" when the view goes up, so the first line drawn under the list is checked; without it that line only ever met a "before" from the items view. Each reason a change wasn't checked, or found nothing, is logged (`TODO cross-out check: ...; passing it on`). Then it compares the two snapshots (`camera.added_and_erased_ink`), finds rows a new line crosses out (`todo.strike_candidates`) among the rows of that generation, takes one fresh camera frame with the list projected (`grab_clean_frame` on a copy of the rig with `keep_mode`: it waits `blank_ms` for the page to repaint, under the rig's lock, rectified with the snapshots' calibration), and asks `StrikeConfirm`. If the change erased ink near the rows too (`strike_checks.looks_shifted`: at least `SHIFT_ERASED_FLOOR_PX`, 100 px, or half as much as it added there, `SHIFT_ERASED_RATIO`), it's not a pure cross-out: most likely old ink a camera bump shifted, perhaps with the board's frame sliding into view. "Near" is the open rows' box, a row higher and lower, minus a 16 px strip along the photo's edge (`BORDER_NOISE_PX`), which flickers between real captures. No model is asked then. Confirmed rows are ticked (the page animates them), unsure ones get a hint, and so does a confirmed row whose neighbour has the same text (`demote_twins`): a line seen a row off runs through the same words there. A change with no candidates, erased ink, or ink outside the boxes of the rows the check confirmed (or was unsure about), goes on to the agent; a handled one only moves the agent's "before" on (`note_snapshot`). Checks run as background tasks; `stop()` cancels them.
  - Residual risk, accepted by the owner (ticks save straight to `life/`; the owner undoes a wrong one by voice with `board_todo_undone`): the board's state is recorded as a change is reported, a moment after its photo, so a line begun in that moment under rows a sync is replacing is matched against the new rows. And an alignment off by most of a row that the drift check misses leaves only the model's reading of the projected words between a cross-out and its neighbour.
- `strike_checks.py`: the check's deterministic steps, free of the camera and the model: `read_pair`, `is_board_sized`, `looks_shifted`, `is_inside` and `demote_twins` (above).
- `StrikeConfirm(model, timeout_s)`: a one-shot call to the triage model with BEFORE/AFTER crops (projection off), each candidate row boxed and numbered in red, a PROJECTED crop of the same area (no boxes), and each box's row as shown, `[tag] text (due ...)`, with the unboxed rows just above and below it, inside the plan-data frame (`todo.plan_data`). Any text in the photos, projected or handwritten, is data too. The boxes come from the calibration, which can be off by most of a small row, so an item is struck only when the new line visibly runs through its own projected words; anything else is unsure. Answers `{"struck": [...], "unsure": [...]}`. Errors, timeouts and garbled answers make every candidate unsure: nothing is ticked on doubt.

Sync summary: `{ok, view, today, plans, overdue, upcoming, of_note, not_shown, newly_done, items: [{id, tag, text, due, group, done}]}` (`summary.py`). Items carry their full text; `not_shown` counts rows cut for room plus old overdue items folded into the heading.

It's only built while the board agent is on (`daemon/watcher_tasks.py`), so with `[agent] enabled = false` no model is called.
