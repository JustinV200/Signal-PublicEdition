# analysis_chamber.security

The chamber's hard limits, enforced in code under `bypassPermissions` (spec 13, decisions 47 and 48): no outbound sends, no raw web pages in the lead, and no personal-run writes into the Signal repo. Built on a tool-isolation spike (notes not published). The hooks are best effort against a non-hostile agent: the priority is no false positives on normal analysis work, while still catching the obvious variants.

## Public API

- `disallowed_tools(role) -> list[str]`: layer 1, the `disallowed_tools=` value. `allowed_tools` restricts nothing under bypass, so this is how the allowlist is enforced: built-ins that fetch, message, notify, publish or schedule (`WebFetch`, `WebSearch`, `SendMessage`, `SendFile`, `SendUserMessage`, `SendUserFile`, `PushNotification`, `RemoteTrigger`, `Artifact*`, `PublishPlugin`, `CronCreate`, `CronDelete`, `ScheduleWakeup`, and `Monitor`, which runs shell commands the shell hooks don't see), the outbound list (`OUTBOUND_TOOLS`, including every claude.ai connector and the chamber's own `mcp__analysis-chamber` stdio server), the role's extras (signup: `Bash`, `PowerShell`), and every known Signal MCP tool not on the role's allowlist (bare `mcp__server` when the role uses none of it). Roles: `lead`, `critic`, `qa`, `signup`. An unknown role raises `ValueError`.
- `allowed_mcp_tools(role) -> list[str]`: the read-only MCP allowlist. Lead: mail reads, rcs reads, `brief_get`. Critic and qa: none. Signup: a browser (docker `browser-docker` preferred, desktop `browser` as fallback; no upload, no `fill_login`) and mail reads. `mcp__chamber__*` is always allowed on top.
- `mcp_servers_for(role) -> set[str]`: the `.mcp.json` server names the allowlist needs, so the agents builder loads only those (with `strict_mcp_config=True`).
- `build_hooks(ctx, role="lead", *, extra=None, content_type_checker=head_content_type) -> dict[str, list[HookMatcher]]`: the `hooks=` value. All PreToolUse, every hook wrapped so an exception becomes a deny (fail closed), and every matcher's timeout set to 30 s:
  - `send_block_hook` on every tool (layer 2): re-checks layer 1 and denies by default any `mcp__` tool that isn't on the role's allowlist. In the signup role, mail tools other than `mail_accounts` must name the configured signup account as `account`.
  - `shell_send_hook`, `page_fetch_hook`, `env_file_hook` and (when `ctx.manifest.personal is not False`) `personal_write_hook` on `Bash|PowerShell|Write|Edit|MultiEdit|NotebookEdit`.
  - For roles `lead` and `qa`, `raw_read_hook` on `Read|Grep|Glob|NotebookRead|Bash|PowerShell`.
  - `extra` matchers per event (e.g. the agents package's PostToolUse free-text swap) are appended after these.
- The hooks themselves (SDK `HookCallback` signature, the keyword argument bound with `functools.partial`): `send_block_hook(..., role=, signup_account=)`, `shell_send_hook(..., ctx=)`, `page_fetch_hook(..., checker=)`, `personal_write_hook(..., ctx=)`, `env_file_hook(..., ctx=)`, `raw_read_hook(..., ctx=)`. `ContentTypeChecker` is `Callable[[str], str | None]`; `head_content_type` is the default (5 s HEAD; failure blocks).

The signup agent has to be its own SDK session built with role `"signup"`, both for `disallowed_tools("signup")` and for `build_hooks(ctx, "signup")`. It can't be an `AgentDefinition` inside the lead, because the lead's layer 1 denies the whole browser server and that deny also applies to its sub-agents.

## What the content hooks check

Each one reads shell commands (headless Windows sessions get PowerShell, not Bash) and the text of script files being written (`.py .ps1 .psm1 .sh .bash .bat .cmd .ipynb`). For Edit, MultiEdit and NotebookEdit that's the whole file as it will be after the edit, not just the new text. That covers `python -c`, heredoc bodies, and scripts the lead writes and runs later with `python code/x.py`.

- **shell_send** ([rules/shell_send_rules.py](rules/shell_send_rules.py)): `gmcli`; Signal tool CLIs in command position (`mail send-self`, `rcs`, `sessions`, ...): at a line start, after `;&|`, in a `(` subshell at a statement start, inside `$(`, `{` or backticks (unquoted), after `analysis-chamber gpu --`, after `uv run`'s options (also as a list, `['uv', 'run', 'rcs']`), after prefix words (`then`, `do`, `else`, `time`, `nohup`, `xargs`, `env`, `FOO=1`), and as the argument of `Start-Process`, `start`, `cmd /c`, `powershell -c`, `bash -c`, `Invoke-Expression`, `subprocess.*` (string or list), a bare list-form `run([`, `Popen([`, `call([`, `check_call([` or `check_output([` (after `from subprocess import run`) and `os.system`. `{ $_.mail }` is fine, since `$` can't start a CLI name. In `.py` and `.ipynb` files only the `uv run` and Python launcher forms count, so a bare `usage` line in a method chain, a `-- mail volume` SQL comment or `print('Start mail parsing')` is fine. Words after `uv run python x.py` are arguments, so `--kind mail` is fine. Also: imports at a statement start (`import X`, `import os, X`, `from X[.y] import`, `python -m X`, `importlib.import_module('X')`, `__import__('X')`) of Signal tool modules, `analysis_chamber` itself, and Google auth or send libraries (`smtplib`, `google.oauth2`, `googleapiclient`, `twilio`), not the word "from" in a comment; `--project/--directory/--from` pointing into `tools/` or `packages/`, and any absolute path under them outside `tools/analysis-chamber`; `analysis-chamber` with any subcommand but `gpu` and `install` (`--help` is fine; in `.py` and `.ipynb` files only in the `uv run` and Python launcher forms, so a `"analysis-chamber research"` User-Agent string is fine); `git push`; `gh`; credential and state files by name (any `.state` folder, `token.json/.bin/.pickle`, `spotify-token.json`, audiohub's `.cache`, `google_client.json`, `client_secret*.json`, `signal-vault`, `daemon.json`, `.ssh`, `.aws`, ...), so `tokenizer.json` and `token_usage.json` pass; mail, SMS and messaging send hosts (SMTP, Gmail and Calendar APIs, `oauth2.googleapis.com`, `messages.google.com`, Twilio, SendGrid, Mailgun, Slack, Discord, Telegram, ntfy, the GitHub API). Paths inside the chamber's own folder (its venv's `analysis-chamber.exe`, the playbook) are allowed, except its `.state` files.
- **page_fetch** ([rules/fetch_rules.py](rules/fetch_rules.py), [head_check.py](head_check.py)): `#` and `<# #>` comments are stripped first, and so are URLs inside chart captions and labels (`figtext`, `fig.text`/`ax.text`, `set_title`, `suptitle`, `annotate`, `set_xlabel`/`set_ylabel`, `title=`/`caption=` keywords), so `requests.get(<FRED API>)` with `plt.figtext('Source: https://fred...')` is allowed. Page scrapers, by import or call (`read_html(`, `BeautifulSoup(`, `import bs4`, `from playwright`, `selenium.webdriver`, ...), are always denied; the bare word (`df.kind == 'newspaper'`) isn't. Fetching code counts as: `curl`, `wget`, `iwr`/`irm`/`Invoke-WebRequest`, `Start-BitsTransfer`, `urlopen`, .NET web clients; a request call on an HTTP library (`requests.get(`); an import of one (`import requests as rq`, `from httpx import get`) plus a URL literal or a request call; and pandas readers whose argument is a URL literal (`read_csv('https://...')`; a reader of a local file in a script that also holds a citation URL isn't a fetch). A bare library name (`uv pip install httpx`, `urllib3.disable_warnings()`) doesn't count. Fetching code is allowed only if every URL literal is data: a data-file suffix (`.csv .json .xlsx .parquet .zip` ...), a data-format query (`?format=csv`), a known data API host (FRED, Yahoo Finance, Hugging Face API, Kaggle API, Census, World Bank, BLS, EIA, SEC, Open-Meteo), or a HEAD Content-Type that is data. At most 5 URLs get a HEAD check, in parallel within 12 s in total; any left unchecked count as pages. A fetch with no literal URL is denied. `.xml`, `.txt`, `.pdf` and `.html` count as pages. A HEAD answered with an error status (405, 403) still counts by its Content-Type. The deny reason points to `mcp__chamber__chamber_fetch`; when some of a fetch script's URLs are data and others aren't, it also says citation-only URLs belong in `sources.json` or another file.
- **personal_write**: file tools are checked exactly with `guard.is_under` (relative paths resolve against the run folder; `..`, case, `/` vs `\` and Git Bash `/c/...` are handled). Shell and scripts are checked one statement at a time (line, `;`, `|`, `&&`): a statement that names a path under `repo_root` and writes (`Set-Content`, `Out-File`, `to_csv`, `open(..., 'w')`, `[IO.File]::WriteAllText`, `git add`, `git -C <repo> add`, ...) is denied, except a copy (`cp`, `copy`, `Copy-Item`, `xcopy`) whose destination, its last argument, is outside the repo. An output option naming a repo path (`--out`, `-o`, `-OutFile`, `--dest`, ...) is denied anywhere, and in shell text (commands and `.ps1`/`.sh`/`.bat` scripts) so is a redirect (`>`, `>>`, `2>`) whose target is in the repo. `>` in Python is a comparison and doesn't count. So reading a life/ file and writing into the run folder is allowed, but a one-line `pd.read_csv(<repo path>).to_csv('data/x.csv')` is one statement that names a repo path and writes, so it's still denied: split it over two lines.
- **env_file**: `<repo_root>/.env` (path in env `CHAMBER_ENV_FILE`) can be read by code, and the shell-send rules don't treat it as a credential file. Write/Edit of it is denied, and so are shell commands that name it (or `CHAMBER_ENV_FILE`) together with a write verb, a print verb or a redirect into it (a redirect elsewhere with `.env` in a comment is fine) (`cat`, `type`, `Get-Content`, `Select-String`, `jq`, ...), and inline code or scripts that print the whole file (`print(open(...).read())`, `print(Path(...).read_text())`, `pprint(dotenv_values(...))`), so keys stay out of the transcript. Reading a key by name is allowed, and so is `uv run --env-file`. Only the chamber's own code (`chamber_get_api_key`) appends to it.
- **raw_read** (lead and qa only): denies Read and NotebookRead into `<run>/data/raw/signal/` (not `signal.csv` beside it); Grep or Glob rooted inside it; and Grep or Glob rooted at or above it (`path` defaults to the run folder, so a Grep with no `path`, or `path: data`, counts) unless the search is kept out of it ([raw_search.py](raw_search.py)). Raw Signal files are always `<nnn>-<tool>.txt`, so a glob is fine when it can't reach the folder (`data/raw/*.csv`; a Grep glob without `/` matches at any depth) or its last segment only matches other extensions (`**/*.csv`, `**/*.png`, `*.{py,ipynb}`), and so is a Grep `type` other than `txt` or `all`. A glob that could match `.txt` there (`*`, `*.txt`, `*.t?t`, `!*.csv`, `**`) or names raw/signal is denied, and Grep's `glob` is judged even with a `type`, since ripgrep's `-g` overrides `-t`. The deny reason says to pass `path` as `code/`, `data/clean/`, `extracts/` or similar. Grep's `pattern` is a regex and isn't read as a path. Shell commands are denied when a print or search command (`cat`, `Get-Content`, `grep`, `jq`, `python -m json.tool`, ...) names the folder itself (also joined to the tracked folder, so `cd data/raw; cat signal/1.txt` counts), or reads a file after a `cd` / `Set-Location` / `pushd` / `Push-Location` into it earlier in the same command. The folder is followed across statements (`cd data/raw; cd signal; cat a.txt`, `(cd data/raw/signal && cat a.txt)`) and left again by popd / Pop-Location or the subshell's closing `)`; popd with nothing pushed stays put, as in the shell. Inside the folder a bare `*` or `.` counts as a file, and a search verb (`grep`, `rg`, `findstr`, `Select-String`) at a statement start reads the cwd even without a path. A recursive shell search or listing (`rg`, `grep -r`, `findstr /s`, `-Recurse`, `find`) rooted at or above the folder is judged like a Grep tool call ([common/shell_search.py](common/shell_search.py) turns its path words, `-g` / `--include` / `-Filter` glob and `-t` type into Grep's `path`, `glob` and `type`): `rg invoice`, `grep -r x .` and `findstr /s x *.txt` are denied, `rg invoice code/ data/clean/`, `rg -t py x` and `grep -r --include=*.csv x .` are fine, and the deny reason asks for a path like `code/` or `data/clean/`. A listing of the folder (`gci` inside it, `ls data/raw/signal`, `gci -Recurse` above it) piped into a print verb anywhere later in the pipeline is denied (`gci | gc`, `| ForEach-Object { Get-Content $_ }`, `| xargs cat`), so `ls | wc -l` there is fine but `ls | head` isn't. That deny's reason suggests listing code/ or data/clean/, or narrowing with `-Filter *.csv` / `-name '*.csv'`. `find ... -exec cat {} \;` counts as a print over everything find lists. `rg --files` and `--type-list` take no pattern, so `rg --files code` is fine. On the right of a pipe a command reads stdin: `python code/count.py | head -5` is fine inside the folder, and so is a piped search's quoted pattern (`... | grep -c 'x.y'`) or a piped `rg x` with no path. Python reading those files for counts is allowed.

## Remaining risk (best effort, an open decision for the user)

The content hooks match text, so they're easy to get around on purpose: obfuscated or base64-encoded code, strings built at run time, a URL or path in a variable defined in another file, a script downloaded and then run, env-var indirection (`$env:APPDATA`), `cd` into the repo in one call and a relative write in the next, languages outside the scanned suffixes (R), inline code in other interpreters (`node -e "fetch(...)"`, `Rscript -e`), a pandas reader handed a URL in a variable (`pd.read_csv(URL)`), `ftp://`, a generic HTTP POST to a host not in the list, or a server lying about its Content-Type. Gaps the per-statement checks add on purpose, to avoid false positives: a repo path in a variable on one line of a script and the write on another; a copy whose destination isn't its last argument; a listing piped into a print verb when the listing isn't of raw/signal or recursive above it (`echo a.txt | xargs cat` after a cd in); shell search flags read as path words when they aren't known value flags (`rg --max-columns 5 x` reads `5` as the pattern), quoted paths with spaces, and an unquoted piped pattern with a `.` inside the folder is denied (`| grep x.y`); a ` #` inside a string cuts the rest of that line from the URL scan; a caption call's own string arguments aren't URL-checked (a fetch call inside one still is); a `cd` into data/raw/signal in one call and a print in the next; and in shell text, a Signal CLI word right after `{`, `$(` or a backtick reads as a command even inside a string (`echo "{ mail 3 }"` is denied), while a `(` only counts at a statement start. Likewise, a prose line in a shell here-string or heredoc (`@"..."@`, `<<EOF`) that starts with a Signal CLI name is denied, because of the line-start rule. A script can print a single `.env` key or loop over its lines. The `mcp__claude_ai_*` prefix glob in layer 1 is unverified across server names (the spike tested globs within one server), so the known connectors are also named; layer 2 denies the rest either way. The MCP layers (1 and 2) are exact. The shell and script checks only stop an agent that isn't trying to hide. Things that would close the gap, such as a network sandbox or a separate OS user without access to the token files, are out of scope here.

## Layout

- `common/`: helpers every hook shares (hook outputs and fail-closed, tool-input text and edits, paths). See [common/README.md](common/README.md).
- `rules/`: the data (tool lists, allowlists, fetch and shell-send patterns, and the write, redirect and print verbs in `file_verbs.py`).
- One module per hook, plus `head_check.py` (URL shape and bounded HEAD checks), `raw_search.py` (whether a Grep or Glob reaches `data/raw/signal`, also used for shell searches) and `hooks.py` (`build_hooks`).

## Depends on

`analysis_chamber.guard` (`is_under`) and `claude-agent-sdk` (`HookMatcher`). It uses `analysis_chamber.agents.context.RunContext` as a type only (`TYPE_CHECKING`), since `agents` imports this package.
